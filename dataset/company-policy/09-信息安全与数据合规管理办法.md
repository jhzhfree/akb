# 信息安全与数据合规管理办法

> 文件编号：SEC-POL-09　|　版本：V4.0　|　生效日期：2026-02-01　|　有效期至：2027-01-31
> 归口部门：信息安全部　|　会签：法务与合规部　|　审批：总经理办公室

## 一、数据与系统分级

| 级别 | 定义 | 示例 | 管控要求 |
|---|---|---|---|
| L4 极密 | 泄露将造成重大损失或法律责任 | 支付密钥、客户资金数据、未公开财报 | 加密存储、最小授权、全量审计、禁止外发 |
| L3 机密 | 泄露将造成较大损失 | 客户合同、员工薪酬、源代码、生产配置 | 加密存储、授权访问、操作审计 |
| L2 内部 | 内部使用，泄露影响有限 | 内部制度、项目文档、周报 | 内部可见，禁止外发 |
| L1 公开 | 可对外公开 | 产品介绍、公开文档 | 无特殊管控 |

## 二、账号与访问控制

- 统一身份认证（SSO + MFA），生产系统须开启双因素认证；
- 权限按**最小必要**原则授予，按角色授权，禁止共享账号；
- 生产权限申请走 OA 审批，有效期最长 90 天，到期自动回收（与运维规范 OPS-RULE-02 对齐）；
- 离职、转岗当日回收全部账号与密钥，回收记录留存 1 年。

## 三、数据外发与共享

| 场景 | 要求 |
|---|---|
| 客户数据共享 | 法务审核 + 客户授权 + 脱敏（去标识化） |
| 外包/厂商访问 | 签署保密协议 + 专用账号 + 操作录屏 + 到期回收 |
| 数据导出至本地 | 禁止导出 L3/L4 数据；确需须信息安全部审批并加水印 |
| 对外演示 | 使用脱敏数据，禁止使用真实客户与资金数据 |
| 代码外发 | 禁止上传至公共代码托管平台；开源须走法务审批 |

## 四、终端与网络

- 办公终端须安装终端管理与防病毒软件，开启全盘加密；
- 禁止私自搭建无线网络出口、禁止使用未审批的远程控制工具；
- 生产网络与办公网络隔离，访问生产须经堡垒主机（KosBastion 4.2）；
- 禁止在生产主机上执行与工作无关的命令（如 `history -c`，属 L1 违规）。

## 五、安全事件分级与响应

| 等级 | 判定 | 响应时限 | 上报 |
|---|---|---|---|
| 一级 | 数据泄露、资金损失、生产被入侵 | 15 分钟内响应 | 总经理 + 法务 + 信息安全部 |
| 二级 | 疑似入侵、影子账号、越权访问 | 1 小时内响应 | 信息安全部 + 运维部 |
| 三级 | 终端中毒、钓鱼邮件、违规外发 | 4 小时内响应 | 信息安全部 |

事件处置流程：发现 → 上报（不得隐瞒）→  containment（冻结账号/隔离主机）→ 取证 → 根因 → 整改 → 报告。

> 运维侧的高危命令拦截事件（如 IC-2026-08-0009）按二级安全事件处理，由安全审计员负责取证与复核。

## 六、日志与审计

- 生产操作全程通过堡垒主机录屏，日志留存 **180 天**；
- 数据库操作由 DB-Audit 独立留存；
- 权限变更、数据导出、密钥使用必须留痕，审计日志保留 1 年；
- 每季度由信息安全部抽查 10% 的高危操作录像，抽查结果报总经理办公室。

## 七、密码与密钥

| 项目 | 要求 |
|---|---|
| 账号密码 | 长度 ≥ 12 位，含大小写数字符号，90 天更换 |
| 生产密钥 | 存放于密钥管理系统，禁止硬编码与明文配置 |
| API 凭证 | 按服务发放，定期轮换（≤ 180 天），离职即回收 |
| SSH 密钥 | 个人密钥加密保护，禁止共享 |

## 八、合规要求

- 遵守《个人信息保护法》《数据安全法》与行业监管要求；
- 个人信息收集遵循「告知—同意—最小必要」，保存期限不超过业务必需；
- 跨境数据传输须经法务与合规部审批；
- 每年至少一次全员安全与合规培训（必修 4 学时）。

## 九、违规处理

| 行为 | 定性 |
|---|---|
| 泄露 L3/L4 数据 | 一级违规，可解除劳动合同并追究法律责任 |
| 共享账号、绕过堡垒主机 | 一级违规 |
| 违规导出数据到本地 | 二级违规 |
| 未及时回收离职账号 | 二级违规（追究资源负责人） |
| 终端未安装管控软件 | 三级违规，限期整改 |
