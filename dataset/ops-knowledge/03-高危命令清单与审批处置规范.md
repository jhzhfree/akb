# 高危命令清单与审批处置规范

> 文件编号：OPS-RULE-03　|　版本：V4.0　|　生效日期：2026-06-20　|　有效期至：2027-06-19
> 归口部门：运维部　|　审批人：王强（E10087）　|　复核：陈静（安全审计员，E10612）

## 一、命令分级

生产环境命令按破坏半径分为三级，**L1 为最高危**。分级与处置动作如下。

| 等级 | 判定标准 | 典型命令 | 处置动作 | 审批要求 |
|---|---|---|---|---|
| L1 | 不可逆、影响全局或多租户 | `rm -rf /`、`drop database`、`kubectl delete ns`、`iptables -F`、`useradd -o -u 0` | 拦截 + 二次确认 + 实时告警 | 运维总监 + 安全审计员双签 |
| L2 | 影响单服务但可恢复 | `chmod -R 777`、`redis-cli FLUSHALL`、`kubectl scale --replicas=0`、`truncate table` | 阻断并转审批流 | 直属主管 + 值班台 |
| L3 | 影响配置或局部 | `systemctl restart`、`nginx -s reload`、`kill -9 <pid>` | 记录 + 事后抽查 | 值班台登记即可 |

## 二、完整高危命令清单（节选）

| 命令 | 等级 | 风险说明 | 推荐替代方案 |
|---|---|---|---|
| `rm -rf /` 或 `rm -rf /*` | L1 | 删除根目录，系统不可恢复 | 使用 `rm` 指定具体目录，先 `ls` 确认 |
| `rm -rf <应用目录>` | L1 | 误删应用目录导致服务不可用 | 先备份至 `/data/backup`，再执行 |
| `drop database <db>` / `drop table <t>` | L1 | 数据不可逆丢失 | 走 DBA 审批，先做全量备份 |
| `truncate table <t>` | L2 | 快速清空表，binlog 不可回滚 | 改用带条件的 `delete` + 备份 |
| `update <t> set ...`（无 where） | L2 | 全表误更新 | 必须带 `where` 并先 `select` 验证 |
| `chmod -R 777 <dir>` | L2 | 全域开放权限，造成权限敞口 | 精确到 750/640 与属主 |
| `chown -R root:root <dir>` | L2 | 应用失去写权限 | 指定应用属主 `app:app` |
| `redis-cli FLUSHALL` | L2 | 缓存全清导致数据库雪崩 | 按 key 前缀删除 `redis-cli --scan` |
| `kubectl delete ns <ns>` | L1 | 删除命名空间及全部资源 | 使用 `kubectl scale` 或删除单个资源 |
| `kubectl scale --replicas=0 deploy/<name>` | L2 | 服务缩容至零，业务中断 | 缩容到最小值 1 或使用暂停发布 |
| `iptables -F` | L1 | 清空防火墙规则，暴露端口 | 逐条删除规则 |
| `history -c` | L1 | 清除操作痕迹，视为违规 | 禁止执行 |
| `useradd -o -u 0 <name>` | L1 | 创建影子 root 账号 | 禁止执行 |
| `systemctl stop <关键服务>` | L2 | 服务中断 | 走变更窗口与审批 |

## 三、拦截与处置流程

```text
命令输入 → 堡垒主机实时匹配规则库
   ├─ L1 命中 → 立即拦截 + 弹窗二次确认（需输入工单号）+ 告警推送值班台与安全审计员
   ├─ L2 命中 → 阻断并转审批流（主管 + 值班台），审批通过后 30 分钟内有效
   └─ L3 命中 → 放行并记录，事后按 5% 比例抽查
```

被拦截的命令**必须**关联 ITSM 工单号，无工单号的 L1/L2 命令一律不得放行。

## 四、实时告警与审计

- L1 命中：企业微信「高危操作」群 + 电话呼叫值班台与安全审计员，5 分钟内必须有人认领；
- 每次拦截生成审计记录，字段包含：会话 ID、操作人、主机、命令原文、等级、处置结果、关联工单；
- 审计记录同步至 KosAudit，留存 180 天，供月度审计与合规抽查调阅。

## 五、例外与紧急处置

故障止损场景下，若审批链路会显著扩大故障影响，允许**先执行后补审**：

1. 执行人电话通知值班台与安全审计员，获得口头授权；
2. 执行后 30 分钟内在 ITSM 补开工单并填写原因、影响与恢复情况；
3. 安全审计员在 24 小时内完成复核，未补单的按一级违规处理。

## 六、违规处理

- 绕过拦截（如通过脚本、管道、变量拼接规避匹配）：一级违规，暂停权限 30 天；
- 执行 `history -c`、`rm -rf /`、创建影子账号等：立即终止会话、冻结账号并启动安全事件调查；
- 外包与外部厂商人员触发 L1：终止合作并留存证据。

## 七、与告警分级的关系

高危命令拦截事件统一按《监控告警与分级响应机制》定为 **P1 告警**，即使未造成业务影响，也必须在 30 分钟内完成认领与说明。
