# 堡垒主机操作审计溯源标准作业流程（SOP）

> 文件编号：SOP-AUDIT-001
> 版本：V2.1，生效日期：2026-07-01
> 适用场景：高危命令告警、数据破坏类事件、账号异常行为核查
> 执行角色：安全审计员、运维工程师、DBA、应用负责人

## 溯源目标与时限要求

- 溯源目标：还原操作人、操作时间、来源 IP、目标资源 IP、资源账号、完整命令序列与回显，形成可归档的证据链。
- 一级告警（例如 `rm -rf /`、`drop database`、`FLUSHALL`）必须在 30 分钟内启动溯源。
- 二级告警（例如 `chmod 777`、服务重启类）必须在 4 小时内完成核查并给出结论。
- 全部证据必须在 24 小时内完成固化归档，归档编号规则为 `AUD-年-月-日-三位序号`，例如 `AUD-2026-08-12-003`。

## 步骤一：确认告警事实与定级

1. 在日志审计平台 KosAudit 中打开告警详情，记录告警编号、命中命令、目标资源 IP 与时间戳。
2. 核对告警是否由堡垒主机的命令拦截策略产生，区分「已拦截未执行」与「已执行并造成影响」两种状态。
3. 依据《堡垒主机高危命令清单与处置规范》POL-BASTION-002 确定命令等级为 L1、L2 或 L3。
4. 定级为一级时，立即通知运维主管王强（工号 `E10087`）与安全审计员陈静（工号 `E10612`）。

## 步骤二：锁定会话与操作人

1. 在 KosBastion 4.2 的「会话审计」模块按目标资源 IP 与时间窗检索会话，取得会话编号。
2. 用会话编号在 ITSM 中反查会话工单，确认是否有双人复核记录；没有工单即定性为违规操作。
3. 记录操作人姓名、工号、所属团队与用工性质（内部员工或外包驻场）。
4. 记录来源 IP 并核对是否为堡垒主机出口地址；来源 IP 为非堡垒机出口时，说明存在绕行通道，需要立即封堵。

## 步骤三：导出完整命令与回显

1. 打开会话录像文件 `.cast`，定位到命中命令的时间点前后各 5 分钟。
2. 导出命令级审计日志，必须逐条包含时间戳、命令原文、执行目录、返回码与回显摘要。
3. 数据库类操作必须额外从数据库审计系统 DB-Audit 导出 SQL 原文，并与堡垒主机日志交叉验证。
4. 导出内容不得裁剪回显中的错误提示，错误提示常用于确定实际影响范围。

使用的导出命令示例：

```bash
# 查询某资源在某时间窗内的全部命令审计
kosaudit session list --resource-ip 10.20.13.7 --start "2026-08-12 20:00" --end "2026-08-12 23:00" --format json
# 回放指定会话编号的录像并导出文本
kosbastion replay --session AUD-2026-08-12-003 --export /evidence/AUD-2026-08-12-003.txt
# 按命令关键字全局检索历史命中记录
kosaudit command search --keyword "rm -rf" --since 30d --level L1
```

## 步骤四：判定影响范围

1. 依据回显与被操作对象路径，判断影响是文件级、服务级还是数据级。
2. 数据级影响必须核对最近一次备份时间与可恢复点目标（RPO），并确认是否可以从备份恢复。
3. 服务级影响必须核对受影响的业务实例数量与流量占比，由应用负责人给出业务损失口径。
4. 影响范围必须写成「受影响对象清单」，且每一条都要有对应的命令或回显作为证据。

## 步骤五：证据固化与归档

1. 对导出的命令日志、录像文件与报表计算 SHA-256 摘要，并将摘要写入证据清单。
2. 证据目录结构固定为：`/evidence/归档编号/{原始命令日志, 会话录像, SQL 原文, 证据清单}`。
3. 证据清单必须写清提取人、提取时间与见证人，见证人不得与操作人存在直属关系。
4. 归档完成后在 ITSM 中回填归档编号，形成「告警 → 会话 → 工单 → 证据」的闭环链路。

## 步骤六：输出结论与改进项

1. 结论必须回答四个问题：谁做的、做了什么、造成什么影响、是否合规。
2. 合规判定依据 POL-BASTION-001：是否有效会话工单、是否双人复核、是否在授权有效期内。
3. 改进项必须可验证，例如「在命令库新增 `rm -rf /data/*` 的 L1 拦截条目」，禁止写「加强管理」这类不可验证表述。
4. 改进项责任人必须有明确姓名与闭环时限，闭环时限不得超过 10 个工作日。

## 常见核查失败原因与处理

- **会话录像缺失**：说明录像开关未对该资源生效，需要在 KosBastion 4.2 上补开并回溯最近的会话。
- **命令回显被清洗**：回显中敏感字段被脱敏策略隐藏时，需要到目标主机本地 history 或 bash 审计日志复核。
- **操作人否认操作**：以堡垒主机人员账号的 MFA 认证日志为归因依据，禁止以来源 IP 作为唯一依据。
- **数据库操作与堡垒机日志对不上**：以 DB-Audit 的 SQL 原文为准，并核查是否使用了本地直连账号。
