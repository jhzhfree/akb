# 堡垒主机审计知识库检索质量评测用例集

> 配套数据集：`../`（堡垒主机审计素材集）
> 用途：把素材导入知识库后，用本用例集逐条提问，检验不同难度下的检索与问答质量
> 提问方式：控制台「知识检索 / 问答」，或直接调用外部接口 `POST /api/v1/external/query`

## 使用方法

1. 将 `dataset/bastion-audit/` 下全部 md 文件导入同一个知识库（建议单独建库，避免与既有知识混淆）。
2. 等待摄入完成：在「任务中心」确认全部文档状态为完成，并在「知识对象」中确认卡片与断言数量不再增长。
3. 按本文件逐条提问，每条记录四项结果：召回是否正确（期望文档是否出现在引用中）、答案是否正确（是否包含期望要点）、是否误答、是否该拒答而未拒答。
4. 记录每一条的 `queryId`，便于在「查询历史 / 链路回放」中对比 failure 原因（召回缺失、融合排序靠后、重排丢失、闸门拒答）。
5. 建议做两轮：一轮默认参数，一轮调整 `topK` 或重排开关后再测，比较同一条用例的差异。

## 评分标准

| 维度 | 判定标准 |
|---|---|
| 召回正确 | 期望文档的片段出现在 Top5 候选或 citations 中 |
| 答案正确 | 答案覆盖期望要点且不出现与之矛盾的表述 |
| 引用正确 | 引用标题或路径能对应到期望文档，可直接点开溯源 |
| 拒答正确 | 知识库未覆盖时明确说明证据不足，而不是编造内容 |
| 冲突处理正确 | 存在多口径时给出时间限定，或指出不同来源的差异 |

**常见失败模式速查**

- **召回缺失**：期望文档完全没进 Top5 —— 多为该文档的分块跨越了 900 字符窗口导致关键句被切断，可尝试切到 `STRUCTURE` 或 `PARENT_CHILD` 策略再测同条用例。
- **召回在后**：命中但排在 5 名之后 —— 多为重排被同主题的其他文档压制，可检查是否出现了标题高度相似的多份规范。
- **答案漏要点**：召回正确但答案不完整 —— 多为上下文拼接丢掉了表格行（表格被渲染成「列名: 值」的行，跨行信息容易丢）。
- **误用相近实体**：例如把 db-mysql-01 与 db-mysql-02、张伟与赵鹏混淆 —— 可在评测时特意追问「资源 IP 是多少」迫使模型回到引用的原文。
- **不该拒答而拒答**：多为证据闸门过严，可对比相似用例在召回正确前提下的答案表现。
