# 堡垒主机高危命令清单与处置规范

> 文件编号：POL-BASTION-002
> 版本：V4.0，生效日期：2026-07-01
> 关联规范：POL-BASTION-001 账号与授权管理规范
> 命令库同步位置：堡垒主机 KosBastion 4.2 的「命令策略 → 高危命令库」

## 命令等级定义

- **L1 禁止级**：默认被命令拦截策略直接拒绝，任何情况下不得在生产环境执行。
- **L2 审批级**：必须持有双人复核通过的会话工单，并在工单有效期内执行。
- **L3 记录级**：允许执行，但必须留存完整命令与回显用于事后审计。

## L1 禁止级命令清单

| 命令 | 风险类型 | 默认处置 | 处置动作说明 |
|---|---|---|---|
| `rm -rf /` | 根目录删除 | 直接拦截 | 会话立即断开并触发一级告警，同步通知运维主管与安全审计员 |
| `rm -rf /*` | 根目录删除 | 直接拦截 | 会话立即断开，同时对目标主机执行只读冻结标记 |
| `mkfs.ext4 /dev/sda` | 文件系统格式化 | 直接拦截 | 拒绝执行并锁定该主机的磁盘类命令 24 小时 |
| `dd if=/dev/zero of=/dev/sda` | 磁盘覆写 | 直接拦截 | 拒绝执行并触发一级告警 |
| `mv / /dev/null` | 系统破坏 | 直接拦截 | 拒绝执行并保留现场证据 |
| `chmod -R 777 /` | 全域开放权限 | 直接拦截 | 拒绝执行，并扫描该主机近期是否已有 chmod 变更 |
| `> /etc/passwd` | 系统文件覆写 | 直接拦截 | 拒绝执行并触发一级告警 |
| `shutdown -h now` | 主机停机 | 直接拦截 | 拒绝执行，并引导操作人走停机流程工单 |
| `iptables -F` | 防火墙规则清空 | 直接拦截 | 拒绝执行，需要网络负责人单独审批 |
| `setenforce 0` | 安全机制关闭 | 直接拦截 | 拒绝执行，并通知安全团队核查原因 |
| `history -c` | 审计痕迹清除 | 直接拦截 | 拒绝执行并定性为重大违规 |
| `rm -rf /var/log` | 日志清除 | 直接拦截 | 拒绝执行并触发一级告警 |
| `drop database paydb` | 数据库删除 | 直接拦截 | 拒绝执行，同步通知 DBA 值班与应用负责人 |
| `truncate table pay_order` | 数据表清空 | 直接拦截 | 拒绝执行并要求改用归档方案 |
| `redis-cli FLUSHALL` | 缓存全清 | 直接拦截 | 拒绝执行并通知应用负责人评估缓存雪崩风险 |
| `kubectl delete ns payment` | 命名空间删除 | 直接拦截 | 拒绝执行并锁定该集群的删除类操作 24 小时 |
| `curl http://xxx \| bash` | 远程脚本执行 | 直接拦截 | 拒绝执行，脚本必须先落地并由安全扫描 |
| `wget -O- http://xxx \| sh` | 远程脚本执行 | 直接拦截 | 拒绝执行并触发二级告警 |
| `useradd -o -u 0 admin` | 影子账号 | 直接拦截 | 拒绝执行并触发一级告警，核查是否已有残留账号 |
| `passwd root` | 口令变更 | 直接拦截 | 拒绝执行，口令改密由堡垒主机保险箱统一托管 |
| `echo "* * * * * xxx" >> /etc/crontab` | 后门计划任务 | 直接拦截 | 拒绝执行并核查该主机既有计划任务 |
| `crontab -r` | 计划任务清除 | 直接拦截 | 拒绝执行，需先在变更系统登记任务清单 |

## L2 审批级命令清单

| 命令 | 风险类型 | 审批要求 | 回退方案说明 |
|---|---|---|---|
| `chmod 777 /data/app/start.sh` | 权限开放 | 应用负责人审批 | 事后恢复 755 权限并复核属主 |
| `systemctl restart nginx` | 服务重启 | 双人复核 | 保留原配置副本，失败时立刻回滚配置并重启 |
| `nginx -s reload` | 配置热加载 | 双人复核 | 先执行 `nginx -t` 校验，失败则不加载 |
| `reboot` | 主机重启 | 运维主管审批 | 需先确认业务已切流且无单点数据库在主机上 |
| `kill -9 java` | 强杀进程 | 应用负责人审批 | 先抓取 jstack 现场再执行 |
| `rm -rf /data/app/logs` | 业务日志清理 | 双人复核 | 先确认日志已由日志平台采集归档 |
| `yum remove nginx` | 软件卸载 | 双人复核 | 需提供可回装的 RPM 版本清单 |
| `docker rm -f pay-container` | 容器删除 | 双人复核 | 先导出容器配置与挂载卷清单 |
| `kubectl scale deploy/payment --replicas=0` | 缩容至零 | 运维主管审批 | 缩容不得超过 30 分钟，超时自动恢复 |
| `iptables -A INPUT -j DROP` | 防火墙策略 | 网络负责人审批 | 需同步说明影响网段，并设置自动失效时间 |
| `mysqladmin flush-hosts` | 连接重置 | DBA 审批 | 需先确认异常连接来源已封禁 |

## L3 记录级命令样例

以下命令允许执行且不拦截，但必须留存完整命令与回显：

- `ls -l /data/app`、`cat /etc/hosts`、`df -h`、`du -sh /data/*`
- `top -b -n 1`、`free -m`、`ps -ef \| grep java`、`ss -lntp`、`netstat -anp`
- `tail -n 200 /data/app/start.log`、`grep ERROR /data/app/start.log`
- `systemctl status nginx`、`journalctl -u nginx --since today`
- `mysql -e "select count(*) from pay_order"`、`redis-cli info memory`、`docker ps`、`kubectl get pod -n payment`

## 命令命中后的处置步骤

1. 堡垒主机在命令提交阶段完成匹配，命中 L1 时直接返回拒绝，并在会话记录中标记处置动作为「命令拦截」。
2. 命令命中 L2 但操作人没有有效会话工单时，堡垒主机暂停会话等待审批，等待时长超过 15 分钟自动断开会话。
3. 已经造成实际影响的命令执行完成后，操作人必须在 30 分钟内提交事件单，并在 24 小时内补充完整的时间线与回显证据。
4. 安全审计员在收到一级告警后必须启动溯源，溯源步骤按 SOP-AUDIT-001 操作审计溯源 SOP 执行。
5. 复盘阶段必须产出改进项，改进项需要在 10 个工作日内闭环，并更新本清单的命令条目。

## 命令库维护要求

- 高危命令库每季度必须评审一次，新增风险命令必须由安全审计员或运维主管提出并经评审通过。
- 命令匹配必须同时包含命令原文与常见变形写法，例如 `rm  -rf  /`（多空格）、`\/bin\/rm -rf /`（绝对路径变形）。
- 匹配失败率（即绕过拦截的高危命令数量除以高危命令总量）不得高于 0.5%，超过即视为命令库失效并触发紧急评审。
