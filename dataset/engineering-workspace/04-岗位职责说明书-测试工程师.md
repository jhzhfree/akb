# 岗位职责说明书 · 测试工程师（质量与测试部）

> 岗位编号：RD-JD-QA-04　|　版本：V2.2　|　生效日期：2026-03-01
> 所属部门：研发中心 · 质量与测试部　|　职级区间：P4–P7　|　汇报对象：质量与测试负责人（孙悦 P8）
> 归口：人力资源部　|　Confluence：KOS-HR/JD

## 一、岗位定位

负责支付与订单产品线的质量保障，包括功能测试、自动化回归、性能压测与线上质量度量，对漏测率与发布质量负责。

## 二、核心职责

| 序号 | 职责 | 交付物 | 权重 |
|---|---|---|---|
| 1 | 用例设计与执行：需求评审、用例编写与执行 | 测试用例、执行报告 | 35% |
| 2 | 自动化测试：接口与 UI 自动化，纳入 CI | 自动化脚本、流水线 | 25% |
| 3 | 性能压测：场景设计、压测执行与瓶颈分析 | 压测报告 | 15% |
| 4 | 缺陷治理：缺陷跟踪、复现协助与回归验证 | 缺陷单、回归报告 | 15% |
| 5 | 质量度量与改进：质量指标统计与流程改进 | 质量月报、改进项 | 10% |

## 三、任职要求

| 维度 | P5 | P6 | P7 |
|---|---|---|---|
| 测试设计 | 等价类、边界值、场景法 | 探索性测试、风险驱动 | 测试策略与体系设计 |
| 自动化 | 接口自动化（Python/Java） | UI 自动化、CI 集成 | 测试框架与平台建设 |
| 性能 | 脚本录制与执行 | 压测场景设计与分析 | 全链路压测与容量规划 |
| 定位能力 | 日志分析 | 抓包、链路追踪 | 根因定位与质量建模 |
| 质量度量 | 用例与缺陷统计 | 质量指标体系 | 质量门禁与流程治理 |

## 四、关键绩效指标（KPI）

| 指标 | 目标 | 说明 |
|---|---|---|
| 漏测率 | ≤ 3% | 线上缺陷中本应发现的占比 |
| 自动化覆盖率 | 接口 ≥ 80%，核心 UI ≥ 50% | 按场景统计 |
| 用例执行率 | 100% | 计划用例执行完毕 |
| 缺陷重开率 | ≤ 5% | 修复后复现比例 |
| 压测覆盖 | 核心链路每季度 ≥ 1 次 | 支付、订单主链路 |
| 发布阻断 | 未达质量门禁不放行 | 一票否决项 |

## 五、质量门禁（发布准入）

| 门禁项 | 阈值 |
|---|---|
| 用例通过率 | 100%（P0/P1 用例） |
| 未关闭 P0/P1 缺陷 | 0 个 |
| 自动化回归 | 全绿 |
| 性能基线 | P99 不高于基线 1.2 倍 |
| 安全扫描 | 无高危漏洞 |
| 日志与监控 | 新增接口有埋点与告警 |

## 六、工作权限

- 测试用例库与缺陷库读写权限；预发环境测试与造数权限；
- 生产只读权限（日志、监控、链路追踪），生产数据修复须走 DBA 流程；
- **质量一票否决权**：未达质量门禁可拒绝放行发布。

## 七、协作接口

| 对象 | 协作内容 |
|---|---|
| 产品经理 | 需求评审、验收标准 |
| 开发 | 提测、缺陷复现与回归 |
| 运维 SRE | 压测环境、监控指标、线上问题定位 |
| DBA | 造数与数据修复验证 |
| 安全 | 安全测试用例与漏洞验证 |

## 八、职业发展

- 纵向：P5 → P6 → P7（测试专家）；
- 横向：可转测试开发（SDET）、质量管理、研发或 SRE；
- 培养：年度 40 学时，其中自动化与性能方向不少于 16 学时。
