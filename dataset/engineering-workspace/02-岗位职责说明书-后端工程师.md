# 岗位职责说明书 · 后端工程师（支付方向）

> 岗位编号：RD-JD-BE-02　|　版本：V2.3　|　生效日期：2026-03-01
> 所属部门：研发中心 · 支付研发部　|　职级区间：P4–P8　|　汇报对象：支付研发负责人（赵鹏 P8）
> 归口：人力资源部　|　Confluence：KOS-HR/JD

## 一、岗位定位

负责支付网关、清结算与风控相关服务的设计、开发与稳定性保障，对支付链路的可用性、正确性与性能负责。

## 二、核心职责

| 序号 | 职责 | 交付物 | 权重 |
|---|---|---|---|
| 1 | 需求开发：按迭代计划完成功能开发与自测 | 可运行的特性、单测覆盖 ≥ 70% | 40% |
| 2 | 方案设计：接口设计、数据模型设计、容量评估 | 设计文档、接口契约 | 20% |
| 3 | 稳定性：参与值班、处理线上告警、止损与根因定位 | 故障处置记录、复盘报告 | 20% |
| 4 | 性能优化：慢 SQL 治理、缓存设计、连接池调优 | 性能优化报告 | 10% |
| 5 | 知识沉淀与带教：文档输出、Code Review、新人带教 | 文档、评审记录 | 10% |

## 三、任职要求

| 维度 | P5 | P6 | P7 |
|---|---|---|---|
| 语言与框架 | Java 17、Spring Boot 3、MyBatis | + 分布式事务、消息中间件 | + 性能调优、故障定位 |
| 数据库 | 基本 SQL、索引 | 执行计划分析、锁与事务 | 分库分表、容量规划 |
| 中间件 | Redis、Kafka 使用 | 缓存与消息设计模式 | 中间件选型与治理 |
| 工程能力 | 单测、CI | 模块化设计、契约测试 | 架构演进、技术评审 |
| 业务理解 | 支付流程 | 清结算与对账 | 资金安全与合规 |

## 四、关键绩效指标（KPI）

| 指标 | 目标 | 说明 |
|---|---|---|
| 需求交付达成率 | ≥ 95% | 按迭代计划完成 |
| 缺陷密度 | ≤ 0.5 个/千行 | 测试与线上缺陷 |
| 线上故障（本人引入） | 0 次 P1、≤ 1 次 P2 | 季度统计 |
| 代码评审通过率 | ≥ 90% | 首次评审通过 |
| 单测覆盖率 | ≥ 70% | 核心模块 ≥ 85% |
| 文档产出 | ≥ 2 篇/年 | 设计、复盘或手册 |

## 五、工作权限

- 代码仓库读写权限（按项目授权）；
- 预发环境部署与调试权限；
- 生产环境只读权限（监控、日志）；生产写权限须按流程申请（OPS-RULE-02）；
- 需求与方案评审的参与权与表决权。

## 六、协作接口

| 对象 | 协作内容 |
|---|---|
| 产品经理 | 需求澄清、验收标准确认 |
| 前端工程师 | 接口契约、联调 |
| 测试工程师 | 提测、缺陷修复、压测支持 |
| 运维 SRE | 发布、监控、应急 |
| DBA | SQL 评审、数据修复 |
| 安全 | 鉴权与资金安全评审 |

## 七、职业发展

- 纵向：P5 → P6 → P7 → P8（见《职级与晋升管理办法》）；
- 横向：可转 SRE、架构、技术管理（M 通道）；
- 培养：每季度至少参与 1 次技术分享，年度 40 学时培训（见《培训与人才发展管理办法》）。
