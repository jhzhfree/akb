1. 产品定位与设计目标

企业级智能知识库平台定位为 AI 原生企业知识平台（AI-Native Enterprise Knowledge Platform）。产品不以“文件管理”或“RAG 参数管理”为用户的第一认知，而以“企业拥有什么知识、知识从哪里来、是否可信、如何被检索和使用”为核心。

知识资产化

将来源、文档、Chunk、实体、关系、断言、证据、知识卡片、图谱与派生知识组织为可管理的企业知识资产。

知识可信化

通过来源、Evidence、版本、置信度、冲突、裁决、权限和审计保证知识可追溯、可判断、可治理。

知识可检索

统一提供关键词、语义、结构化与图关系检索，并支持引用、Trace 与检索质量评测。

知识服务化

知识既供人使用，也通过 API、MCP、SSE 等标准能力提供给业务系统、AI 应用与 Agent。

本次 V2.0 的核心变化：从原来的“工作台 / 知识空间 / 知识生产 / 知识管理 / 知识治理 / 检索中心 / 图谱 / 应用 / 评测 / 系统管理”等多一级入口，收敛为 知识概览（工作台）、知识生成、知识检索、接口服务、系统配置 五个一级菜单。复杂能力进入二级页面、Tab、Drawer 和对象详情页。
本次修订（对齐当前实现）： ① “知识集成”更名为 接口服务：对外交付的是 API / MCP / SSE 接口能力，而不是内部的数据集成； ② 引入 用户视图 / 管理视图：普通用户登录进入用户视图，管理员登录进入管理视图并可在顶栏切换，用户视图只保留“用知识”所需的入口； ③ 顶栏精简为 视图切换 / 知识库 / 全局搜索 / 主题 / 用户，任务与服务状态不再占用顶栏，任务回到“知识生成 · 生成任务”查看； ④ 版本与授权信息统一显示在主内容底部页脚，侧栏底部不再单独显示版本号。

2. 产品布局重构原则

本次布局参考 Google Cloud Agent Search 的产品思路：以 Data Store / Data Source、Document、Search App 等核心资源组织能力，创建过程围绕“选择来源 → 创建数据存储 → 连接应用 → 搜索/预览”展开。我们的平台保留这一“资源少、入口清晰、任务导向”的优点，但增加企业知识生产与可信治理能力。

原则产品设计
一级菜单少而稳定固定五大一级入口，不把 Chunk、断言、图谱、评测等专业对象全部暴露为一级菜单。
首页回答“知识现在怎么样”知识概览聚合来源、文档、卡片、断言、实体/关系、生命周期和治理状态。
创建过程任务化所有“让新知识进入系统”的动作归入知识生成，包括文档导入、连接器、裁决与衍生。
检索能力集中搜索、Retrieval Test、策略、Trace、Benchmark 统一放入知识检索。
消费与开放统一问答/搜索应用以及 API、MCP、SSE 统一归入接口服务。
技术参数后置模型、索引、用户、权限、字典、任务等进入系统配置；普通知识用户不需要理解底层技术。
按视图裁剪入口同一套 IA 有两种视图：管理视图含生产流水线与运维/测评入口，用户视图只保留“用知识”的入口；差异由视图切换即时生效，不是两套产品。

左侧导航（对齐当前实现）：业务入口按业务域分组展示——工作台：知识概览；知识库：知识生成、知识检索；系统集成：接口服务。系统配置属于低频平台配置，不进业务分组，收在侧栏底部工具区的齿轮入口（与用户区同一行）。原二十余个功能入口全部进入对应主页面，以 Tab、卡片、快捷操作、Drawer 和对象详情承载；其中“知识图谱”归入“知识检索”，“知识集成”更名为“接口服务”。
知识库（Knowledge Base）不再作为一级菜单。它作为全局作用域存在于顶部知识库选择器中。切换知识库后，五个一级菜单均自动作用于当前知识库；平台管理员可切换“全部知识库”。
3.x 两种视图（本次新增）：同一套 IA 按登录人角色呈现两种视图，差异只体现在“模块内 Tab 与管理类入口”，一级菜单保持不变。
用户视图（普通用户默认）：知识概览与当前一致；知识生成只保留 文档导入（默认进入）/ 知识裁决 / 知识衍生；知识检索保留 搜索 / 检索测试 / 检索策略 / 知识图谱，不含检索链路追踪与检索评测；接口服务只保留 服务。
管理视图（管理员默认）：模块内完整 Tab，包含生成概览、连接器、生成任务、检索链路追踪、检索评测、接口服务的协议配置 / 凭证 / 调用日志等运维入口。
管理员可在顶栏随时切换两种视图用于核对普通成员看到的界面；切换后若当前页在目标视图不可见，自动回落到该模块的默认页。
3.z 登录页（对齐当前实现）：登录是全站唯一的无框架页，采用左右分栏：左侧品牌区（主标题“让知识随时被 AI 调用” + 副标题 + 三条价值点），右侧表单区（用户名 / 邮箱、密码、记住账号、忘记密码、登录按钮）。不提供任何第三方登录方式：企业微信与 SSO 入口已移除，登录只用账号密码；管理员入口与普通用户登录共用同一页，通过页脚入口互相切换。登录后默认进入“知识概览 · 首页”。
3.y 顶栏与底部（本次调整）：顶栏从左到右为 品牌 → 视图切换 → 知识库切换 → 全局搜索 → 主题切换 → 用户（头像 / 姓名 / 退出）；任务入口与服务连接状态不再占用顶栏，异步任务在“知识生成 · 生成任务”页内查看与跟踪。版本与授权信息统一显示在主内容底部页脚（产品版本 + 运行环境 / 服务版本 + “企业自部署 · 版本与授权由部署镜像管理” + 版本信息入口），侧栏底部不再单独显示版本号。

4. 一级菜单一：知识概览（工作台）

知识概览是产品默认首页，目标不是展示系统功能，而是在一个页面回答：“当前企业知识资产有多少？从哪里来？处于什么生命周期？是否可信？哪里需要处理？”

4.4 生命周期视图

以漏斗/流水线展示当前知识资产处于哪个阶段。用户点击阶段即可进入对应对象集合。生命周期统一定义为：

Source → Document → Parse/Clean → Chunk → Extract → Assertion / Entity / Relation → Derive → Adjudicate → Knowledge Card / Graph → Index / Publish → Retrieve / Apply → Evaluate / Feedback → Update / Expire

4.5 快速入口

工作台提供 导入文档新增连接器待裁决知识衍生知识搜索检索测试。专业对象不再占用左侧一级导航。

5. 一级菜单二：知识生成

“知识生成”覆盖一切让新知识进入平台、变成可信知识资产的过程。用户不需要理解后台的 Parser、Embedding 或 Index 服务，只需要选择来源、确认处理结果并完成治理。

视图差异：用户视图下知识生成只保留 文档导入（默认进入）/ 知识裁决 / 知识衍生；生成概览、连接器与生成任务属于生产流水线的运维入口，只在管理视图开放。

5.1 首页

文档导入

拖拽上传、本地文件、URL、手工文本；支持批量导入与导入历史。

连接器

数据库、API、对象存储、企业协作平台等持续同步型来源。

知识裁决

处理冲突、低置信、版本不一致、证据不足等待治理知识。

知识衍生

基于可信断言、关系、规则和计算生成新的候选知识。

5.2 文档导入

Step 1 选择知识空间 → Step 2 选择文件 / URL / 文本 → Step 3 设置解析策略（默认推荐，可展开高级设置） → Step 4 上传并解析 → Step 5 查看解析结果 / Chunk → Step 6 自动抽取知识 → Step 7 审核候选知识 → Step 8 发布

导入页默认只展示业务友好的配置：知识类型、标签、权限、处理模式。OCR、Chunk Strategy、Embedding 等进入“高级设置”。

5.4 外部知识

按外部系统的类型与属性浏览连接器同步下来的条目（文档、工单、记录等），用于核对“同步进来了什么、哪些还没进知识生产”。该入口是连接器的伴生视图，属于生产流水线运维范围，只在管理视图开放。

5.5 知识裁决

裁决不是单独的后台管理模块，而是“知识生成完成前的可信化环节”。页面采用冲突列表 + Assertion 对比 + Evidence 原文 + 系统建议 + 人工决策。

5.6 知识衍生

衍生页分为“衍生规则”“候选衍生知识”“衍生记录”。系统必须区分原文直接知识与派生知识；派生项保存 derivedFrom、方法、规则/算法版本、证据链、置信度和状态。

6. 一级菜单三：知识检索

知识检索同时服务普通知识查找与知识工程调优。默认是简洁搜索体验，高级能力通过 Tab/高级模式展开。

6.1 页面结构

知识检索 ├─ 搜索（智能问答） 默认入口：自然语言 / 关键词 两种视图 ├─ 检索测试 对召回结果与 Score 进行调试 两种视图 ├─ 检索策略 Retrieval Profile 两种视图 ├─ 检索链路追踪 查看一次查询完整链路 仅管理视图 ├─ 知识图谱 实体关系探索、路径分析、图谱检索 两种视图 └─ 检索评测 批量评测与回归 仅管理视图
菜单去重：智能问答（搜索）页面内部不再重复一排“检索测试 / 检索策略 / 检索链路追踪 / 检索评测”的菜单，检索模块的所有入口统一由页面顶部的模块 Tab 承载；一次问答的链路详情通过结果卡片上的“查看完整链路”进入 Trace 抽屉。

6.2 知识搜索

搜索结果不只返回 Chunk，而优先展示“知识卡片 / 断言 / 文档 / 实体”等知识对象；结果卡片展示来源、Evidence、版本、状态与相关知识。支持按来源、知识类型、标签、时间、状态过滤。

6.3 检索测试

区域能力

RecallBM25 / Vector / Metadata / Graph 等候选

6.4 检索策略

将复杂参数封装为可复用 Retrieval Profile，例如“通用知识检索”“制度精确检索”“产品技术检索”“图谱影响分析”。普通用户只选择策略名称，知识工程师才能编辑高级参数。

6.5 知识图谱

知识图谱不再作为独立一级菜单，也不作为知识概览的主要功能入口，而是归入“知识检索”，作为一种面向关系、路径与上下文的高级检索方式。用户可从搜索结果中的实体、断言或关系进入图谱，也可直接切换到“知识图谱”Tab。

能力产品说明
实体搜索按实体名称、类型、属性定位中心实体。
关系探索以中心实体展开 1~N 跳关系，查看实体、关系、断言与 Evidence。
路径分析分析两个实体之间的关联路径，用于影响分析、依赖分析与问题定位。
图谱检索Graph Recall 作为多路召回的一部分，与 BM25、Vector、Metadata 等共同参与融合和重排。
证据回溯图节点和关系可回到 Assertion、Evidence、Document，保证图谱结果可解释、可追溯。

7. 一级菜单四：接口服务

接口服务（原“知识集成”）负责把已经生产和治理好的知识，以标准协议和服务接口开放给业务系统、AI 应用与 Agent。对外交付的是 API / MCP / SSE 接口能力，而不是内部的数据集成。

视图差异：用户视图下接口服务只保留 服务 一个 Tab——调用方只需要知道有哪些服务、怎么接；接口概览、协议配置（API / MCP / SSE）、凭证与调用日志属于发布与运维侧，只在管理视图开放。面板内的“凭证”区块（API Key 的签发、吊销与调用审计）同样只出现在管理视图。

7.1 服务

服务是接口服务的主体对象，也是用户视图下的唯一入口：一个服务绑定知识库范围、Retrieval Profile、协议（REST / MCP / SSE）、凭证与限流策略，对外暴露 Search / Retrieve / Answer / Knowledge Object 四类能力。服务页展示服务卡片（名称、能力类型、协议、状态）与接入说明；创建与配置服务在管理视图的“接口概览 → 创建服务”完成。

7.2 接口概览

展示已创建的集成服务、调用量、成功率、P95 延迟、Token/模型消耗、最近错误。支持创建“集成服务”，每个集成服务绑定知识空间、Retrieval Profile、权限策略和访问凭证。

7.3 API

能力用途
Search API返回排序后的知识对象
Retrieve API返回供外部 LLM/Agent 使用的 Evidence Context
Answer API平台完成检索、上下文装配、生成与 Citation
Knowledge API读取 Card、Assertion、Entity、Evidence、Lineage

7.4 MCP

将搜索、检索、知识对象读取等能力作为 MCP Tools/Resources 暴露，使 AI Agent 可以按权限使用企业知识。MCP 调用与 Web UI 使用同一 ACL、Retrieval Profile 与 Trace。

7.5 SSE

SSE 用于 Answer/Agent 类长耗时调用的流式输出。事件至少包含 start、retrieval、citation、delta、complete、error；前端可逐步展示“正在检索 → 已找到证据 → 正在生成 → 完成”。

7.6 凭证与调用日志

集成服务级管理 AppKey/Token、允许来源、限流、过期时间和权限范围。调用日志支持 traceId 反查 Query、检索结果、引用、耗时和错误。

调用日志（对齐当前实现）：日志列表除时间、服务、协议、状态码、延迟与 Trace 外，直接展示明文的传入参数与返回数据（如 {"query":"…"}、{"results":5,"evidence":3}），便于调用方自查接入问题；敏感字段按系统配置的脱敏规则处理。REST / MCP / SSE 三种协议的调用统一落库，明细可在调用日志中展开查看。

11.1 用户视图 / 管理视图

角色决定“能不能做”，视图决定“看见多少”。管理员登录后进入管理视图，可在顶栏一键切到用户视图，用来核对普通成员实际看到的界面；普通账号固定为用户视图，顶栏的切换项保持可见但不可点，并给出原因提示。视图选择写入本地存储，刷新后保持。

12. 关键业务流程

12.1 从文档到可信知识

知识生成 → 文档导入 → 解析预览 → 自动抽取 → 候选 Assertion + Evidence → 冲突检测 → 必要时裁决 → Knowledge Card → 发布 → 工作台资产统计 / 知识检索可见

12.2 从连接器到持续知识

创建 Connector → 首次同步 → 生成 Document/Record → 知识生产 → 发布 → 定时/事件增量同步 → 检测变更 → 旧知识失效/重算 → 新版本发布

12.3 从问题到知识服务

用户/API/MCP Query → Query Rewrite → BM25 + Vector (+ Graph/Structured) → ACL → RRF → Rerank → Evidence / Card / Assertion → Answer + Citation → Trace + Evaluation
