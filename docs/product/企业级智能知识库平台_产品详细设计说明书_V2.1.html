1. 设计基线与总体原则

知识生成主页面交互约束：左侧不再出现“文档导入、连接器、生成配置、知识台账、知识裁决、知识衍生”等二级菜单。主页面顶部使用四个任务入口卡片：导入文档 / 连接数据源 / 知识裁决 / 知识衍生；下方使用 生成概览 / 生成配置 / 文档导入 / 连接器 / 外部知识 / 知识台账 / 知识裁决 / 知识衍生 Tab 组织完整工作区。

详细设计承接 PRD V2.1，将产品从“功能模块集合”重构为围绕知识资产的五个用户任务域：看知识、建知识、找知识、接知识、管平台。

知识概览看知识
知识生成建知识
知识检索找知识
接口服务接知识
系统配置管平台
术语调整：“接口服务”（原“知识集成”）比“知识应用”更准确。该一级菜单的核心不是在平台内创建各种终端应用，而是把可信知识能力通过 API、MCP、SSE、凭证等方式接入现有业务系统、AI 应用、Agent 与工作流。

2.3 用户视图 / 管理视图

视图是角色之上的一层“信息密度开关”：角色决定能不能操作，视图决定看到多少入口。实现上由外壳统一计算当前视图（adminView = 管理员角色 && 视图模式='admin'），页面内 Tab 与区块按它裁剪，页面自身不重复判定角色。

模块用户视图管理视图增量
知识概览知识仪表盘 / 知识库工作台 / 知识资产 / 知识版本 / 知识质量—
知识生成文档导入（默认进入）/ 知识裁决 / 知识衍生生成概览、生成配置、连接器、外部知识、知识台账
知识检索智能检索 / 检索测试 / 检索策略 / 知识图谱检索链路追踪、回答反馈、检索评测

2.4 底部页脚（版本与授权）

主内容区最下方固定一条页脚，所有页面共用：左侧为产品名 + 产品版本徽标 + 运行环境/服务版本（取自 /api/knowledge/env，未取到时省略），右侧为授权说明「企业自部署 · 版本与授权由部署镜像管理」与「版本信息」入口（打开版本信息弹窗：服务版本、运行环境、核对时间、检查更新）。侧栏底部不再单独显示版本号。

2.2 主题与视觉规范（深浅双主题）

呈现层不再按页面各自调色，所有组件只消费一套主题 token：同一个语义在深色与浅色下取不同值，组件只写“主文本 / 次级表面 / 成功态”这类语义，不写具体色值。新增一个主题只需新增一组变量，不改任何组件。

2.2.1 主题切换与作用域

项规则
切换入口顶栏右侧；切换后整站（含顶栏、侧栏、弹窗、抽屉、表格、图谱画布、登录页）同步变化。
三档循环点击在 浅色 → 深色 → 跟随系统 三档间循环（图标 ☀ / ☾ / ◐），与实现一致；跟随系统档实时响应 prefers-color-scheme。
持久化本地存储保存选择（dark / light / system），刷新与重新登录保持；未选择时默认浅色。
作用域主题作用于根节点的 data-theme，所有变量在该作用域下重定义；组件无需感知当前主题。
对比度正文与背景对比度不低于 4.5:1；弱化文字不低于 3:1；状态色在两种主题下都必须落在“可读”区间。

2.2.3 按钮三档

档位形态用于两主题表现
主操作品牌色实心 + 白字 + 品牌色边框页面唯一主行动点：生成知识、开始导入、发布服务形态一致，仅品牌色深浅不同
次操作表面底 + 可见边框 + 主文本刷新、重试、预览、批量操作边框在深色下必须可见，否则会退化成一块看不出边界的深色
弱操作无边框 + 次级文字，hover 才出现底色取消、关闭、次要链接同上
危险操作危险色实心 + 白字删除、停用、废止同上
切换类按钮（如“文档 / 文本分块 / 实体归一”）统一写成「次操作 + 选中即切主操作」，并依赖样式层顺序保证主操作覆盖次操作；禁止用透明度、下划线或自绘底色表示选中。

2.2.4 状态三件套与状态胶囊

任何位置展示“成功 / 警告 / 失败 / 进行中 / 中性”，一律使用同一枚状态胶囊：底色 + 字色 + 边框三件套由主题给出，深浅各一套。

2.2.5 第三方组件的主题桥接

表格、标签、按钮、进度条、弹窗、分页等基础组件来自 Element Plus，其默认皮肤是浅色的。做法是把组件的 CSS 变量整体接到本套 token 上（背景、文字、边框、填充、状态色及其浅色变体），使它们在深色主题下自动变成深色底 + 亮色字，在浅色主题下使用本套状态色，而不需要逐个组件写主题分支。

收益：状态色在“自己写的胶囊”和“第三方组件的标签”上完全一致；新增主题时第三方组件自动跟随。

2.2.6 实施纪律

禁止替代做法
在组件里写固定调色板色（如“浅绿底 + 深绿字”）使用状态胶囊类，配色由主题给出

4. 知识生成详细设计

路由：/knowledge/generate。页面顶部 Tab：生成概览 / 生成配置 / 文档导入 / 连接器 / 外部知识 / 知识台账 / 知识裁决 / 知识衍生。

视图裁剪：用户视图只渲染 文档导入 / 知识裁决 / 知识衍生，且默认落在「文档导入」；生成概览、生成配置、连接器、外部知识、知识台账仅管理视图可见。过滤后剩下的第一个可见 Tab 即用户视图的默认落点，不需要额外配置默认页。

4.1 文档导入向导

Step 1 来源 → Step 2 文件/URL/文本 → Step 3 知识属性 → Step 4 处理策略 → Step 5 执行与结果
步骤字段规则
来源知识空间、来源名称、来源类型空间默认当前值
内容File/URL/Text批量文件显示大小、类型、重复检测
知识属性知识类型、标签、权限、有效期权限默认继承空间，可收紧
处理策略标准/高质量/自定义高级设置才暴露 Parser、Chunk、模型
执行Pipeline Progress异步；允许离开页面，任务中心继续跟踪

4.2 连接器

连接器列表使用卡片+表格混合视图：类型、名称、同步状态、最后同步、对象数、权限策略。创建流程统一为“选择类型 → 认证 → 范围 → 字段/权限映射 → 同步策略 → 测试连接 → 创建”。

4.3 外部知识

按外部系统的类型与属性浏览连接器同步下来的原始条目，用于核对「同步进来了什么」。列表字段：条目、来源系统、类型、同步时间、状态（已同步 / 待确认 / 失败）。属于连接器的伴生视图，随连接器一起只对管理视图开放。

4.4 解析/抽取结果

用户点击任务进入任务详情，展示 Document → Parse → Chunk → Extraction → Evidence → Candidate Knowledge。专业用户可打开“原文/结构/Chunk”三栏工作台。

5. 知识检索详细设计

路由：/knowledge/search，顶部 Tab：智能检索｜检索测试｜检索策略｜检索链路追踪（Query Trace）｜知识图谱｜回答反馈｜检索评测（Benchmark）。「检索测试」与「检索链路追踪」属于调试类页面：配置区 + 结果区 + Trace 抽屉。

视图裁剪：用户视图只渲染 智能检索 / 检索测试 / 检索策略 / 知识图谱；检索链路追踪、回答反馈与检索评测属于检索质量的调试与测评入口，仅管理视图可见——普通成员不需要用它们完成“找知识”。
菜单去重：智能检索页内不再重复一排与顶部 Tab 相同的导航菜单。检索模块的所有入口统一由页面顶部 Tab 承载；单次问答的链路详情从结果卡片的「查看完整链路」进入 Trace 抽屉，问答历史列同样可点开完整链路。

5.1 智能检索

[自然语言或关键词................................] [搜索] 过滤：来源 | 知识类型 | 标签 | 状态 | 时间 | 对象类型 结果 1 [知识卡片] 标题 / 摘要 来源 · Evidence · 版本 · ACTIVE 关联断言 5 · 相关实体 3 [查看详情] 结果 2 [断言] ...

默认混合返回 Card、Assertion、Document、Entity。结果对象必须显示来源与状态，禁止只返回无法解释的向量片段。

5.2 检索测试

左侧 Query/策略配置，右侧结果；结果展开 Score Breakdown：BM25、Vector、RRF、Rerank、Business Weight。点击“Trace”打开 Drawer 查看各阶段输入输出与耗时。

5.3 Retrieval Profile

Profile 采用“基础设置 + 高级设置”。基础设置仅包含知识范围、搜索模式、TopK；高级设置包含权重、阈值、RRF K、Reranker、Graph Expansion、Context Window。

5.4 检索评测（Benchmark）

数据集管理、运行历史、版本对比。至少显示 Hit@1/3/5、Recall@K、Citation Accuracy、Latency；P1 增加 MRR/NDCG/Faithfulness。

5.5 检索链路追踪（Query Trace）

以 traceId 为单位查看一次问答的完整链路：查询理解、多路召回、融合排序、重排、上下文装配与生成，以及各阶段耗时、模型与索引版本。列表按时间倒序分页（10 / 20 / 50 / 100 条每页，带总数与页码），避免长列表一次拉全量；排序在时间戳之外补 id DESC，否则同一秒的多条记录翻页会重复或漏行。每行展示调用方 IP（按 X-Forwarded-For、X-Real-IP 解析，取不到记为空不影响其它列），便于把异常调用定位到具体来源。从智能检索结果卡片与问答历史的「查看完整链路」可直达对应链路。

5.6 回答反馈

收集真实问答中暴露的问题与修正建议（答错、引用不准、缺失知识等）。反馈不直接改写知识：经人工确认后才进入知识治理流程，避免未核实的反馈被写进知识库。每条反馈关联到当时的 trace，可回溯检索与生成过程。

5.x 知识图谱检索工作区（V2.1 新增）

知识图谱属于“知识检索”主页面内部的高级检索 Tab，不新增左侧菜单。其定位不是独立的图数据库管理后台，而是帮助用户通过实体、关系、路径和 Evidence 理解“知识之间为什么有关联”。

6. 接口服务详细设计

接口服务（原“知识集成”）负责把平台的可信知识能力安全、标准化地开放给外部系统。设计上参考成熟云产品的“数据资源与服务资源分离”思路：知识资产本身与面向调用方的集成服务是不同对象。

视图裁剪：用户视图只渲染 服务 一个 Tab，且默认落在「服务」；接口概览、API、MCP、SSE、凭证、调用日志属于发布与运维侧，仅管理视图可见。面板内的「凭证」区块同样按视图裁剪（API Key 的签发、吊销与调用审计只在管理视图渲染），否则用户视图下会从面板内部绕回凭证管理。

6.5 MCP

MCP 页面分为 Server 配置、Tools/Resources 列表、权限范围、测试控制台和调用日志。建议首批工具：search_knowledge、retrieve_context、get_knowledge_card、get_assertion、get_evidence、explore_entity。MCP 不建立第二套权限模型，复用集成服务 Credential + Knowledge ACL。

6.7 凭证

凭证字段：credentialId、name、type(API_KEY/OAUTH/JWT)、serviceIds、scopes、ipAllowlist、rateLimit、expireAt、status。Secret 仅创建时显示一次；列表只显示尾号。

6.8 调用日志

字段：time、service、protocol、client、requestId、traceId、status、latency、retrievalCount、tokenUsage、errorCode、callerIp（调用方 IP），以及传入参数（requestParams）与返回数据（responseData）。点击 traceId 跳转 Query Trace，形成“外部调用 → 检索 → Evidence → Answer”的完整追溯。调用方 IP 按 X-Forwarded-For → X-Real-IP → 直连地址的顺序解析，取不到记为空，不影响其它列。

明文入参与返回（对齐当前实现）：调用日志在列表与详情中直接展示传入参数与返回数据的明文内容（REST 的请求体与响应体、MCP 的工具入参与结果、SSE 的增量与完成事件），便于调用方自查；展示前按系统配置的脱敏规则处理敏感字段。REST / MCP / SSE 三种协议的调用统一落库，协议的入参与返回由请求体缓存与响应包装统一采集，避免不同协议各写一套。

6.9 外部主体与多知识库授权

凭证背后是调用主体（Principal），授权挂在主体而不是单个 Key 上：一个主体可持有多个 API Key，也可被授予多个知识库。

项设计
主体应用主体（APPLICATION）与委托员工身份（USER，显式绑定 IdP subject）；存量 API Key 升级时自动转成独立主体，其原单库绑定迁移为等价授权
授权主体 → 知识库的授权记录，含 status、expiresAt、reason；一个主体可同时持有多个知识库的授权
标签上限授权上的 permission_tags：NULL 继承该主体 API Key 的策略，空数组表示仅可访问公开资料
审计授权的授予 / 变更 / 撤销与凭证换绑均落审计表；换绑凭证不删除仍持有共享授权的主体

6.10 事件总线

平台关键事件的持久流水：知识库、摄入、抽取、检索、治理与权限动作都会落一条带事件号的记录，SSE 订阅推送的就是同一份数据。断线后可按事件号接着看，不必重放整条流；页面提供实时订阅开关。

6.11 嵌入组件

选定知识库与外观后生成一段可粘贴的代码，业务页面引入即得一个问答组件，无需自行对接 API。
