## V1.1 ACL Phase 17 — Unified Answer Qualification + Claim Audit Ledger

### 基线审计

本轮以用户提供的 Phase 16 Structured Answer Gate 工程包为唯一基线。压缩包完整性和 Phase 9–16 代码链已核验：

- Phase 14 核心能力已由 V21 `t_exact_evidence_binding` 和精确绑定逻辑吸收。
- Phase 15 包含答案级 Citation Completeness / Faithfulness Gate 与 V22 汇总表。
- Phase 16 包含逐 Claim 的 `SUPPORTED / PARTIALLY_SUPPORTED / CONTRADICTED / INSUFFICIENT` 判断。
- Phase 16 的缺口是结构化 Claim 判断只存在于响应和 Trace，未形成可查询、可回放的权威审计账本。

### Phase 17 实现

#### 1. 统一最终决策

新增 `AnswerQualification`，统一编排 Phase 15 和 Phase 16：

1. Evidence Gate 未通过：`BLOCKED`。
2. Structured Gate 存在冲突或证据不足：`BLOCKED`。
3. Structured Gate 部分支持：`PARTIAL`。
4. 两级 Gate 均通过：`PASS`。
5. Gate 显式关闭或无模型回答：`BYPASSED`，避免把绕过误记为通过。

#### 2. 策略版本与不可逆审计标识

- 新增 `ANSWER_POLICY_VERSION` 配置，默认 `answer-policy-v1`。
- 保存原始答案和最终交付答案的 SHA-256，不保存被阻止的原始答案正文到新增审计表。
- 每个 Claim 带策略版本、Evidence Codes、治理状态、蕴含度、置信度和是否进入最终答案。

#### 3. MySQL 权威审计账本

Flyway V23 新增：

- `t_answer_qualification`：查询级最终资格决策。
- `t_answer_claim_assessment`：Claim 级证据与决策账本。

Query Trace、Phase 15 Assessment、Phase 17 Qualification 和 Claim Ledger 在同一 Spring 事务中写入，避免部分成功。

#### 4. 前端可观测性

Query Trace 新增“答案资格与 Claim 审计”面板，展示：

- 最终 Gate 状态；
- 策略版本；
- Evidence / Structured 两级状态；
- 每个 Claim 的决策、蕴含度和 Evidence Code。

#### 5. 集成优化

- 修复 `check-v11.sh` 未执行 Phase 9/10/12/13/15/16 专项 Gate 的问题。
- 修复英文否定词使用子串匹配导致 `knowledge` 中的 `no` 被误判为否定的缺陷，改为英文单词级匹配。
- 开发和生产环境模板补充答案 Gate 阈值及策略版本配置。

## V1.1 ACL Phase 18 — Answer Quality Operations

### 问题定位

Phase 17 已将统一答案资格与 Claim 决策写入 MySQL，但此前存在“写入闭环、读取未闭环”的问题：

- Trace API 只返回 `t_query_trace`，前端依赖 `trace_json` 内的生成时快照。
- 无法通过独立 API 核验数据库中真正提交的资格记录和 Claim 账本。
- 无知识库级 PASS / PARTIAL / BLOCKED / BYPASSED 统计。
- 无法观察多个 `ANSWER_POLICY_VERSION` 并存时的结果分布。

### 本轮实现

#### 权威资格详情

新增：

- `GET /api/knowledge/answer-qualification/{qid}`

返回查询级资格决策及按顺序装配的 Claim 审计账本。

#### Trace 权威装配

`GET /api/knowledge/trace/{qid}` 现在从资格表读取并注入 `answerQualification`。前端优先展示该字段，仅对历史数据回退到 `trace_json` 快照。

#### 质量运营汇总

新增：

- `GET /api/knowledge/answer-qualifications/{kb}/summary?hours=24`

返回：

- 总查询数；
- PASS / PARTIAL / BLOCKED / BYPASSED 数量；
- PASS Rate、Blocked Rate；
- 策略版本数量；
- 各策略版本的状态分布与最近执行时间。

时间窗口限制在 1 小时至 90 天，避免无界聚合查询。

#### 前端契约

- 增加 `AnswerQualification`、`AnswerClaimAssessment`、`AnswerQualificationSummary` TypeScript 类型。
- 增加资格详情和质量汇总 API。
- Claim Evidence JSON 同时兼容数据库 JSON 字符串和数组形式。

### 验证

- Phase 18 contract：9/9 PASS。
- Mapper、DB、MyBatis XML、Frontend TypeScript、Code Quality 和 Python compileall 继续执行。
- 当前环境缺少 Maven、前端依赖和完整 Python 依赖，因此不宣称真实 Java/Vite/全栈构建通过。

### 下一步

在真实 MySQL 环境执行 V23 后，对 Summary SQL 做数据量压测；随后可增加策略版本 A/B 对比、告警阈值和历史 Trace 离线重评任务。
