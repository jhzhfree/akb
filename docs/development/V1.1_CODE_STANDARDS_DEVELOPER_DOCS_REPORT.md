# V1.1 代码规范审查、注释补强与研发文档化报告

## 1. 本轮目标

本轮基于 `V1.1 Authoritative Rebuild + SLO + RBAC` 版本执行完整代码质量收口，目标不是修改产品功能，而是让代码达到“研发团队可以长期维护、代码评审有统一标准、新工程师可以快速读懂”的状态。

审查覆盖：

- Java / Spring Boot / MyBatis
- Python / FastAPI / Retrieval / Graph / LLM / Reranker
- Vue 3 / Element Plus
- Flyway SQL / XML / YAML / Shell
- Transactional Outbox / Index Worker / Blue-Green Schema Release
- Elasticsearch / Milvus / Neo4j Provider
- CI / 回归 Gate / 开发文档

## 2. 审查前主要问题

### 2.1 Java 公共类型缺少职责说明

大量 Service、DTO、Domain、Configuration、Mapper 只有类名，没有说明它在系统中的边界、是否承担事务、是否允许调用外部服务。对熟悉作者上下文的人问题不大，但新工程师需要不断反向追踪调用链。

### 2.2 Python 检索代码可运行但可读性不足

`external.py`、`indexer.py`、`graph_provider.py` 等核心文件存在压缩式写法、过长表达式、职责聚合。外部 Provider 的幂等 ID、ACL 过滤、Schema Alias、Fallback 语义缺少 Why-level 注释。

### 2.3 Provider 生命周期不够一致

部分 Provider 已经采用进程级单例，而 LLM Provider 仍可能在调用期间重复创建 HTTP Client。高并发时会造成连接池重复建立、资源浪费和行为不一致。

### 2.4 异常降级存在“静默失败”风险

若使用 `except Exception: pass`，虽然可以维持 fallback，但现场排障时无法判断是模型不可用、解析失败还是业务数据问题。

### 2.5 Vue 主页面模板过度压缩

`App.vue` 中存在大量超长单行模板。页面虽然能运行，但修改表格列、按钮权限或面板逻辑时容易产生冲突，也难以在 Code Review 中看清结构变化。

### 2.6 原代码质量 Gate 偏“能运行”，缺少可维护性约束

原 Gate 已覆盖 Java 8 API、Flyway、Mapper、API Contract 等工程正确性，但尚未强制：

- Java 顶级 public 类型 Javadoc
- Java package-info
- Python module/public symbol docstring
- 生产源码行宽
- Tab / trailing whitespace
- silent broad exception
- Provider singleton lifetime
- 前端 API boundary
- 开发文档完整性

## 3. 实际代码改造

### 3.1 Java 代码规范

本轮为 Controller、Service、Configuration、DTO、Domain、Mapper、Exception 等公共类型补充类级 Javadoc，并新增以下包说明：

```text
common/package-info.java
config/package-info.java
controller/package-info.java
domain/package-info.java
dto/package-info.java
mapper/package-info.java
service/package-info.java
```

注释重点不是重复代码，而是解释：

- 类的职责边界；
- authoritative state 与 retrieval view 的关系；
- 哪些方法运行在短事务中；
- 为什么外部 AI / Search 调用不能放进数据库长事务；
- Outbox、Index Worker、Schema Release 的一致性语义。

重点补强：

- `DocumentIngestionService.upload`
- `KnowledgeExtractionService.extract`
- `KnowledgeQueryService.query`
- `KnowledgeGovernanceService`
- `IndexOutboxService`
- `IndexOutboxWorker.poll`
- `IndexSchemaService.rebuild / activate / rollback`

`KnowledgeProperties` 也重新格式化，避免紧凑 getter/setter 影响配置阅读。

### 3.2 Python Provider 与检索层重构

重点重构：

```text
app/services/retrieval/external.py
app/services/indexer.py
app/services/graph_provider.py
app/services/llm_provider.py
app/services/adjudication_engine.py
app/services/extractor.py
app/services/reranker.py
app/main.py
app/core/config.py
```

主要变化：

1. 增加模块、类、公共函数 docstring。
2. Elasticsearch/Milvus Provider 改为结构化方法，显式说明 ACL、状态过滤、稳定 ID、蓝绿 Alias。
3. `indexer.py` 按外部同步、删除、知识对象转换、Schema rebuild/activate 等职责拆分。
4. Graph Upsert 拆成 Entity/Card/Claim/Relation 四个内部方法。
5. Cypher 动态关系类型加入安全白名单原因说明。
6. LLM Provider 改为 `@lru_cache(maxsize=1)` 进程复用，并复用 `httpx.AsyncClient`。
7. Reranker/Graph/Embedding/LLM/External Provider 生命周期统一。
8. LLM、Extractor、Reranker fallback 不再静默吞异常，而是保留可定位日志。
9. 裁决引擎注释明确“规则与确定性评分是治理主决策，LLM Judge 是 advisory input”。

### 3.3 Vue 可读性改造

`frontend/src/App.vue` 重新结构化：

- 模板按 Data Center / Adjudication / Query / Graph 分区；
- 将超长属性行拆分；
- 关键设计处增加 Why-comment；
- 明确“切换 Tab 只加载当前模块数据”用于避免旧版全量 fan-out；
- 明确 Review 面板使用 `Promise.allSettled`，避免单一接口失败导致整个工作台不可用；
- API 调用继续统一经 `src/api/knowledge.js`，页面不直接使用 axios。

`main.js` 同步完成格式规范化。

## 4. 注释策略

本轮没有机械地为 getter/setter 或显而易见的赋值语句增加注释，而采用以下原则：

### 应该写注释

- 事务边界为什么这样设计；
- 为什么选择 fallback；
- 为什么必须先做 ACL filter；
- 为什么旧 Outbox DEAD 会阻塞新版本；
- 为什么 Schema Version 与 object indexVersion 分离；
- 为什么 Provider 必须复用；
- 为什么某段查询必须批量/分页；
- 第三方 API 的容易踩坑约束。

### 不应该写注释

```java
// 获取名称
return name;
```

或：

```python
# 设置状态
status = "APPROVED"
```

目标是降低理解成本，而不是增加注释数量。

## 5. 新代码规范

当前自动 Gate 强制：

| 类型 | 生产源码最大行宽 |
|---|---:|
| Java | 160 |
| Python | 140 |
| JavaScript | 160 |
| Vue | 180 |
| Python 测试 fixture | 200 |

另外强制：

- 禁止 Tab；
- 禁止 trailing whitespace；
- Java 顶级 public class/interface/enum 必须有 Javadoc；
- 核心 Java package 必须有 `package-info.java`；
- Python 非 `__init__.py` 模块必须有 module docstring；
- Python public top-level symbol 必须有 docstring；
- 禁止 `except Exception: pass`；
- 重型 Provider 必须进程级缓存；
- `KnowledgeService` 保持薄 Facade；
- Vue 页面禁止直接绕过 API 层使用 axios；
- Review 并行加载继续使用隔离失败策略。

规范实现位于：

```text
scripts/check-code-quality.py
```

## 9. 本轮没有改变的架构原则

- MySQL 仍是 authoritative state；
- Elasticsearch/Milvus/Neo4j 是可重建 Retrieval View；
- Chunk 是 evidence/context carrier，不是最终知识；
- AI candidate 不能绕过治理直接成为正式知识；
- 外部调用不能拖住长数据库事务；
- Outbox 保证业务状态与索引事件同事务；
- ACL 必须在召回/上下文阶段前置；
- APPROVED/EFFECTIVE 才进入正式知识召回；
- Schema Release 与 object indexVersion 使用不同版本语义。

## 11. 后续进一步规范化建议

后续在具备完整 Maven/npm 环境后，可以逐步引入：

1. Java：Checkstyle + Spotless，并以当前仓库规则作为初始基线；
2. Python：Ruff + Black 或 Ruff Formatter，并保持当前 Provider/异常规则的自定义 Gate；
3. Frontend：ESLint + Prettier + Vue ESLint；
4. 将过大的 `App.vue` 进一步拆为 DataCenter、ReviewWorkbench、SmartQuery、GraphExplorer 页面组件；
5. Backend 的内部 `Map<String,Object>` 继续向明确 DTO / Projection 演进；
6. Ops Token RBAC 最终接入企业 OIDC/SSO/IAM；
7. 将架构 ADR（Architecture Decision Record）加入后续重大设计决策流程。
