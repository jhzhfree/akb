## 1. 版本定位

| 项 | 内容 |
|---|---|
| 版本号 | 1.1.0（首个可交付产品版本） |
| 一句话定位 | 让企业把散落的文档变成**有证据、经裁决、可追溯、会过期**的知识资产，并对外提供**可解释**的智能问答 |
| 目标用户 | 知识运营管理员（主）、业务专家（裁决与纠错）、普通员工（问答）、平台运维（索引与发布） |
| 成功判据 | 新用户可在 **30 分钟内**独立完成「上传资料 → 抽取 → 裁决 → 发布 → 提问 → 追溯到原文」全流程 |
| 交付形态 | Docker Compose 一键部署（MySQL / Redis / Elasticsearch / Milvus / Neo4j / 后端 / AI 服务 / 前端 / Grafana） |

## 3. V1.1 必须补齐的缺口（按优先级）

> 结论：**V1.1 的差距不在后端能力，而在"最后一公里"的前端暴露与身份认证。** 后端已有 54 个端点，其中 18 个前端未接；这些恰恰是"治理"与"发布"两类最能体现产品差异化的能力。

| 序号 | 缺口 | 影响 | 建议方案 | 预估 |
|---|---|---|---|---|
| G1 | 实体与别名管理无界面 | 实体归一价值不可见、无法纠错 | 新增「实体与关系」页签：实体列表、别名、合并来源、人工纠错与解绑 | 4 人日 |
| G2 | 断言新字段未可视化 | 条件化/时态化知识无法被理解 | 断言列表增列极性、有效期、版本、确定性；详情抽屉增「条件与期限」区块 | 3 人日 |
| G3 | 生命周期操作无界面 | 知识过期治理无法交付 | 生命周期页签：状态看板 + 过期扫描 / 版本替代 / 影响分析操作 | 5 人日 |
| G4 | 蓝绿发布与回滚无操作入口 | "可发布可回滚"无法演示 | Ops 面板补 重建 / 激活 / 回滚 按钮，含二次确认与进度反馈 | 3 人日 |
| G5 | Outbox 重放 / 跳过无入口 | 故障自愈需人工敲接口 | Ops 面板补死信重放、跳过操作（受运维 RBAC 保护） | 2 人日 |
| G6 | 索引事件列表未接 | 排障效率低 | Ops 面板增事件表（分页 + 状态筛选） | 2 人日 |
| G7 | 用户登录与身份认证 | 无法区分操作者，审计不完整 | 见 §6 待决策 Q1 | 5—8 人日 |
| G8 | ACL 重建编排未接 | 大规模授权调整不可自助 | 权限面板增重建任务列表与阶段操作（可延后至 V1.2） | 3 人日 |

## 5. 验收标准（Definition of Done）

### 5.1 功能验收

1. **端到端闭环**：新部署环境下，30 分钟内完成 上传 → 抽取 → 裁决 → 发布 → 提问 → 追溯到原文，全程无需调用接口或改库。
2. **证据可追溯**：任一条答案的引用可逐级下钻至 ContentUnit 原文片段，无断裂。
3. **无证据不结论**：构造无相关知识提问，系统必须拒答或明确声明证据不足，不得编造。
4. **治理可操作**：过期扫描、版本替代、影响分析三类操作均可在界面完成并留痕。
5. **发布可回滚**：索引蓝绿重建后回滚一次，回滚后问答结果与重建前一致。
6. **权限不越界**：无权限用户提问，答案中不出现无权证据及其内容。

### 5.2 质量与性能验收

| 维度 | 指标 | 目标 |
|---|---|---|
| 检索质量 | 首批种子语料 Recall@10 | ≥ 0.85 |
| 检索质量 | MRR | ≥ 0.7 |
| 问答质量 | 引用准确率 | ≥ 0.9 |
| 问答质量 | 无答案率（应拒答场景） | ≥ 0.95 正确拒答 |
| 性能 | 问答 P95 延迟（不含 LLM 生成） | ≤ 3s |
| 性能 | 索引进度可见、单文档（≤ 2MB）处理 | ≤ 60s |
| 稳定性 | Outbox Dead Letter | 0 |
| 稳定性 | 索引漂移 | 0 |
| 可用性 | 7×24 连续运行 72 小时无 OOM / 无任务堆积 | 通过 |

### 5.3 交付物验收

- `docker-compose` 一键部署 + `wait-ready.sh` 就绪
- 部署手册、运维手册、备份恢复演练记录
- Go / No-Go 检查清单全部通过
- 产品原型与实现一致（不存在原型有、实现无的核心流程）
