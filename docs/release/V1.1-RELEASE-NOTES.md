## 1. 版本概览

| 项 | 内容 |
|---|---|
| 版本 | **1.1.0**（首个可对外交付的产品版本） |
| 一句话定位 | 让企业把散落的文档，变成**有证据、经裁决、可追溯、会过期**的知识资产，并对外提供**可解释的智能问答** |
| 本次发版主题 | 打通「资料接入 → 知识抽取 → 冲突裁决 → 可信问答 → 生命周期治理」的**端到端闭环** |
| 目标用户 | 知识运营管理员（主）、业务专家（裁决与纠错）、普通员工（问答）、平台运维（索引与发布） |
| 交付形态 | 离线安装包 `ai-knowledge-1.1.0.tar.gz`（默认）/ 容器编排 / 源码裸跑 |
| 部署前提 | Docker 20.10+ 与 compose v2；LLM 与 Embedding 模型服务由客户自备（Ollama 或 OpenAI 兼容网关），不随包交付 |

V1.1 的三条核心价值：

1. **答案必有出处**：每条结论都可下钻到原文片段（Evidence → Source → Document → ContentUnit）。
2. **宁可少答，不可错答**：答案经「证据忠实度 + 结构化 claim」两道门禁裁决，未通过的句子整句剔除，无证据则拒答。
3. **知识会过期**：断言带有效期、版本与极性，支持到期失效、版本替代与来源撤销影响分析。

## 2. 功能总览

### 2.1 系统大模块与实现程度

> 系统由 **5 个大模块** 组成：**用户认证、用户管理、知识库生成、智能问答、系统配置**。下表说明每个大模块要做什么、包含哪些功能点，以及 V1.1 做到什么程度。

| 大模块 | 模块职责（做什么） | 包含功能 | 实现程度 | V1.1 状态说明 |
|---|---|---|---|---|
| **用户认证** | 平台**用户登录过程**（账号体系、登录、会话与身份识别）＋**知识库公开 / 私有权限划分**与库级授权，以及资源级权限控制与访问审计 | 登录与库级可见性（V1.2）＋ 权限、审计与回答侧过滤（F12） | ⚠ 权限就绪 · 登录与公开/私有未提供 | V1.1 **无登录页、无账号体系、无会话、无 SSO**，访问身份由内网网关 / 反向代理注入；知识库表 `t_knowledge_base` **无可见性字段**，不做公开 / 私有划分（全库内网可见），越权靠资源 ACL（`permission_tags`）约束；已具备：资源 ACL 变更即时生效与异步传播、访问审计与 ACL 变更流水、回答侧越权证据过滤、ACL 重建编排（接口级）；V1.2 建设账号体系、登录流程与公开 / 私有库级授权 |
| **用户管理** | 用户的**增删改查**：用户新增 / 编辑 / 停用、角色与用户组绑定、凭据与密码管理 | 主体与角色查看（F13，只读）＋ 用户 CRUD（V1.2） | ⚠ 仅只读查询 · CRUD 未提供 | 现仅有 `/acl/subjects`、`/acl/roles` 两个只读接口，用于权限自查；**无用户实体与持久化表、无新增 / 编辑 / 停用 / 重置密码、无角色绑定、无用户管理界面**（主体以 `subject_code` 形态在 ACL 侧维护）；V1.2 随认证方案落地完整 CRUD 与界面（G7 / G8） |
| **知识库生成** | 从资料到知识资产的生产主链路：多知识库管理、文档接入与解析、知识抽取、实体归一、冲突识别与裁决、生命周期治理 | F1 — F6 | ✅ 主链路完整（治理为 ⚠ 接口级） | F1 工作台、F2 解析、F5 冲突裁决端到端完整；F3 抽取与 F4 归一可用但**质量随所选模型波动**、无实体与别名管理界面；F6 到期失效 / 版本替代 / 影响分析接口可用，**无内置定时调度与治理看板**，需外部触发 |
| **智能问答** | 知识消费出口：问题路由与查询改写、多路召回与融合、答案质量门禁与降级、证据溯源、可解释 Trace、图谱查询 | F7 — F11 | ✅ 完整（门禁 ◐ 可用-受限） | 路由 / 溯源 / Trace / 图谱（F7、F8、F10、F11）端到端完整；F9 双门禁 + claim 级降级闭环可用，但判定为**词面算法**（中文 bigram + 否定词典，非 NLI），Reranker 默认关闭，故标记可用-受限 |
| **系统配置** | **模型配置**（LLM / Embedding provider 与参数、连通性测试、按能力降级）与**其他关联服务配置**（MySQL / Elasticsearch / Milvus / Neo4j / ai-service 的连接参数与健康状态） | 模型配置（F15 主体）＋ 关联服务配置（V1.2） | ◐ 模型配置完整 · 关联服务仅部署配置 | 模型配置 ✅ 完整：`/api/knowledge/settings/model`（读写 + `/test` 连通性测试 + `/env` 生效视角）与「模型设置」面板可用，换模型不改代码，支持 Ollama / OpenAI 兼容 / mock，切换 Embedding provider 或维度**须重建索引**；其他关联服务 ⚠：仅能通过环境变量与 `docker-compose` / `.env` 配置，**无配置界面、无配置写接口**，健康状态只读（`/actuator/health`、能力探测）；V1.2 补关联服务配置界面与连通性切换 |

> **整体判断**：**知识库生成**与**智能问答**两大业务模块已端到端闭环，可对外演示与验收；**系统配置**当前仅「模型配置」可在界面完成配置，其他关联服务仍走部署环境变量；**用户认证**与**用户管理**是 V1.1 最主要的缺口——平台尚无登录过程与用户账号，知识库也无公开 / 私有划分，V1.1 依赖内网部署 + 网关统一鉴权，V1.2 优先补齐（G7 / G8）。
>
> 范围说明：索引运维与蓝绿发布（F14）、监控告警与发版门禁（F15 运维部分）属**部署与运维交付**能力，随安装包交付（compose + Prometheus / Grafana + Go/No-Go 门禁脚本），不计入「系统配置」大模块；其中索引重建 / 激活 / 回滚目前仍为接口级操作（走 API + `X-Ops-Token`）。

实现程度标记：`✅ L4 完整`（端到端闭环、有验收覆盖）· `◐ L3 可用-受限`（有明确边界）· `⚠ L2 后端就绪·前端未接`（需走 API 或运维操作）· `✳ L1 实验性`（默认关闭）· `— L0 未提供`。

### 2.3 各模块实现的功能

#### 知识库管理（F1 — F6）

> 定位：知识从「文档」变成「可治理资产」的生产与管理主链路。

- **已实现**：多知识库与统一工作台（F1）、文档接入与解析（F2）、知识抽取（F3）、实体归一与跨源解析（F4）、冲突识别与智能裁决（F5）、知识生命周期治理（F6，接口级）。
- **V1.1 未提供**：生命周期看板与内置定时调度、连接器自动同步（Confluence / 飞书 / SVN / 对象存储）、跨库联邦检索与库级配额、知识对象物理删除、实体与别名管理界面、断言条件与期限可视化。
- **V1.2 计划**：生命周期界面与调度内置、连接器生态、实体与断言可视化补齐（G1 / G2 / G3）。

#### 知识消费（F7 — F11）

> 定位：面向员工与业务系统的知识使用出口，强调「答得准、可溯源、可解释」。

- **已实现**：智能问答与问题路由（F7）、证据溯源与引用下钻（F8）、答案质量门禁与降级（F9）、问答可解释与 Trace（F10）、知识图谱查询（F11）。
- **V1.1 未提供**：独立问答质量看板、字符级高亮引用、>2 跳图谱检索与社区发现、Reranker 默认能力、多轮上下文引用。
- **V1.2 计划**：质量看板独立页、NLI 语义化门禁、Reranker 内置镜像、图谱增强检索（多跳 / PageRank / 全局摘要）。

#### 系统认证（F12）

> 定位：授权、审计与回答侧过滤；**认证（登录）本身由网关承担**，本模块不含登录界面。

- **已实现**：资源 ACL 变更即时生效与异步传播、访问审计与 ACL 变更流水、回答侧权限过滤、ACL 重建编排（接口级，start / qualify / activate）。
- **V1.1 未提供**：内置登录与身份认证（注册 / 登录 / 会话）、SSO 对接界面、审计导出与留存策略配置、ACL 重建编排界面；运维令牌 `X-Ops-Token` 仅覆盖 `/api/knowledge/index/**` 写接口。
- **V1.2 计划**：认证方案落地（内置账号体系或网关身份透传）、审计导出与留存配置、ACL 重建编排界面（G7 / G8）。

#### 用户管理（F13）

> 定位：访问主体与角色的查看与核对；V1.1 因无账号体系，仅提供只读能力。

- **已实现**：主体清单查询 `/acl/subjects`、角色清单查询 `/acl/roles`（接口级，只读）。
- **V1.1 未提供**：用户增删改、角色编辑、用户-角色绑定、用户组、部门维度授权、用户管理界面。
- **V1.2 计划**：随认证方案（Q1）确定是否建设完整用户与角色管理界面。

#### 系统配置（F14 — F15）

> 定位：索引运维、模型与设施配置、发布与可观测，面向平台运维。

- **已实现**：索引运维与蓝绿发布（F14，接口级：Outbox 指标、死信重放/跳过、漂移检测、重建/激活/回滚）；模型配置与连通性测试、一键部署与就绪等待、健康检查与能力探测、Prometheus + Grafana 监控告警、备份恢复演练、Go/No-Go 门禁（F15）。
- **V1.1 未提供**：重建进度与预计完成时间、索引事件列表、蓝绿发布与死信操作的界面入口、内置定时备份任务、提示词版本管理、Kubernetes / Helm 部署形态。
- **V1.2 计划**：索引运维界面化（G4 / G5 / G6）、定时备份与巡检调度、提示词版本管理与效果 A/B、Helm 形态评估。

## 3. 功能说明、验收标准与约束

> 验收标准（AC）按「客户可在部署环境上亲自执行」编写；涉及接口的条目为 V1.1 前端未暴露能力的临时验收路径。

### F1 多知识库与统一工作台

> 所属模块：**知识库管理**
**做什么**：支持创建、切换、归档多个知识库，各库检索与索引按 `knowledgeBaseId` 物理隔离；工作台提供 11 个页签（概览 / 资料与摄入 / 卡片 / 断言 / 审核 / 图谱 / 问答 / 生命周期 / 运维 / 权限 / 模型）与资产指标、生命周期链路、检索设施状态一屏视图。

**验收标准**

- AC-1：新建 2 个知识库并分别上传文档，在 A 库提问不会命中 B 库内容。
- AC-2：工作台概览能同时展示来源数、文档数、卡片数、断言指标与检索设施可用状态，数据与接口 `/api/knowledge/...` 一致。
- AC-3：11 个页签均可打开且无报错空页；页签切换后刷新页面仍停留在原页签。
- AC-4：知识库归档后不再出现在默认检索范围，历史数据可查。

**约束与备注**：无跨库联邦检索、无库级配额与限流；概览指标为实时聚合，无历史趋势留存；页签状态保存在浏览器本地，非服务端用户偏好。

---

### F2 文档接入与解析

> 所属模块：**知识库管理**
**做什么**：单文件 ≤100MB 上传（`POST /api/knowledge/documents/upload`），首批支持 4 类格式 —— PDF `.pdf`、Word `.docx`、Markdown `.md/.markdown`、纯文本 `.txt`；按 Chapter → Section → Paragraph → Sentence 层级切分，产出可精确定位的 ContentUnit；摄入过程（Source → Parse → Persist → Extract → Index）分阶段留痕；来源可带权威分与 ACL 标签。

**验收标准**

- AC-1：上述 4 种格式各上传 1 份（含 1 份 ≥20 页 PDF），均在 60 秒内完成解析并出现在文档列表，无需人工干预。
- AC-2：打开任一文档可定位到段落级原文，且该段落能在后续问答中被作为证据引用。
- AC-3：上传 >100MB 文件被明确拒绝并给出提示；扫描版 PDF（无文本层）解析为空，并在摄入日志中标记失败阶段。
- AC-4：重复上传同一文件，后端返回去重结果，不产生第二条文档记录。
- AC-5：人为构造一份解析失败文件（如损坏 PDF），可在摄入运行日志中定位到具体阶段与原因。
- AC-6：为来源设置权威分后，其在问答排序中的权重变化可观察（高权威来源优先被引用）。

**约束与备注**：首批仅 PDF / Word / Markdown / 文本四类，不支持 PPT / Excel / HTML / 扫描件 OCR，需先转为带文本层的 PDF、Markdown 或纯文本；Word 仅支持 `.docx`（旧版 `.doc` 需另存为 `.docx`）；复杂表格、多栏版式 PDF 可能出现串行；重复判定在上传后由后端返回，上传前无提示；摄入日志随库保留，无自动清理策略；单文件上限由 `MAX_FILE_SIZE` 控制。

---

### F3 知识抽取（卡片 / 断言 / 实体 / 关系）

> 所属模块：**知识库管理**
**做什么**：由 LLM 从文档抽取知识卡片、断言、实体与关系，抽取载荷包含**限定词、极性、确定性、有效期、别名**等结构化字段；抽取任务由 Outbox 驱动，失败自动重试，死信可查。

**验收标准**

- AC-1：上传一份 ≥10 页的技术文档，系统自动产出卡片与断言，数量与文档中可识别知识点量级相符（不少于 5 条断言）。
- AC-2：抽取出的断言至少覆盖有效期、版本、限定词中的 2 类字段（通过接口或数据库查看）。
- AC-3：人为让 LLM 服务不可用后重新抽取，任务进入重试；恢复 LLM 后任务自动成功，无需人工重放。
- AC-4：连续失败的任务最终进入 Dead 状态，可在 Outbox 指标中看到计数并可重放。

**约束与备注**：**抽取质量强依赖所选模型**，换模型必须回归评测（`scripts/release-quality-eval.py` + 种子集）；当前无抽取结果置信度阈值可视化；进入 Dead 的任务需人工重放。

---

### F4 实体归一与跨源解析

> 所属模块：**知识库管理**
**做什么**：通过「别名词典 + 向量相似度」两级判定（`/ai/entity-resolve`，默认阈值 0.86）合并同一实体的不同叫法，并支持跨文档、跨来源的实体解析。

**验收标准**

- AC-1：准备 2 份文档，其中同一实体使用不同别名（如「K8s」与「Kubernetes」），归一后实体记录合并，别名可查。
- AC-2：跨 2 个来源引用同一实体的断言，可在图谱或实体关联中看到合并后的关系。
- AC-3：构造 2 个语义相近但不同的实体，验证不会被误合并（或误合并后可通过人工纠正解绑）。

**约束与备注**：归一阈值需按语料调优；误合并需人工纠正，**V1.1 无实体与别名管理界面**（缺口 G1），纠错需走 API；跨源解析依赖 embedding 质量，维度变更需重建索引。

### F5 冲突识别与智能裁决

> 所属模块：**知识库管理**
**做什么**：基于断言语义相似度与极性识别知识冲突，提供冲突列表与解决动作（`/conflicts/{id}/resolve`）；提供 AI 智能裁决（加权置信度 + 冲突惩罚）降低人工量，裁决全程留痕；待审核列表支持批准 / 拒绝。

**验收标准**

- AC-1：上传两份对同一事实给出不同数值的文档，系统在冲突列表中识别出该冲突，并展示双方断言与来源。
- AC-2：执行解决动作后，冲突状态变更并在审核流水留痕，后续问答引用被采纳的一方。
- AC-3：待审核列表可完成一次批准与一次拒绝，状态机流转正确，被拒绝内容不进入检索面。
- AC-4：开启 AI 智能裁决后，人工审核量下降（同批量下人工处理条数可减少），且每条 AI 裁决可查看依据。

**约束与备注**：冲突检测基于语义相似度与极性，**非语义 NLI 模型**；无批量审批、无审批流配置；裁决权重为内置策略，不支持界面配置；时态冲突（DISJOINT / OVERLAPPING）后端已区分，前端无差异化提示。

### F6 知识生命周期治理

> 所属模块：**知识库管理**
**做什么**：三类治理动作——
① 到期失效扫描（`POST /api/knowledge/lifecycle/{kb}/expire`，`valid_to < now` → EXPIRED）；
② 版本替代（旧版本 → SUPERSEDED，保留历史）；
③ 来源撤销影响分析（`/lifecycle/sources/{id}/impact`，CARD / CLAIM / ENTITY 影响面）。
另有版本历史与字段级差异对比（`VersionDiffPanel`）。

**验收标准**

- AC-1：构造一条已过期的断言，触发过期扫描后其状态变为 EXPIRED 且不再被引为有效证据。
- AC-2：上传同一知识的新版本文档，触发替代后旧版本置为 SUPERSEDED，历史版本仍可查。
- AC-3：撤销一个来源，影响分析返回受影响的卡片/断言/实体数量，与实际关联数一致。
- AC-4：任取一条有多版本的断言，可在版本差异面板中看到字段级 diff。

**约束与备注**：**三类操作无前端入口**（缺口 G3），验收需走接口或运维脚本；**无内置定时调度**，需外部 crontab / CronJob 触发；替代关系由版本链自动判定，不支持人工指定；影响面为直接关联统计，不做级联传播模拟；生命周期看板 V1.1 未提供。

### F7 智能问答与问题路由

> 所属模块：**知识消费**
**做什么**：统一问答入口，按 8 类问题路由（EXACT / MULTIHOP / CONFLICT / RELATION / CONDITION / PROCEDURE / GLOBAL / FACT）选择不同召回通道；支持查询改写与有界补充召回；多路召回 + 加权 RRF + 质量信号提权 + 可选 Rerank 融合排序。

**验收标准**

- AC-1：分别提出「精确事实」「条件限定」「流程步骤」「多跳关系」「全局统计」5 类问题，答案正确且 Trace 中显示对应路由类型。
- AC-2：使用口语化、省略式问法提问，查询改写生效后仍能召回正确证据（Trace 中可见改写结果）。
- AC-3：LLM 不可用时，问答降级为原句召回并可正常返回，不崩溃。
- AC-4：种子语料上 Recall@10 ≥ 0.85、MRR ≥ 0.7（`scripts/release-qualification-*.py` 实测）。

**约束与备注**：路由为规则 + 信号判定，极端问法可能误路由；改写依赖 LLM；**Reranker 默认关闭**（需在镜像中加装 `torch`/`transformers` 并置 `RERANKER_ENABLED=true`）。

### F8 证据溯源与引用下钻

> 所属模块：**知识消费**
**做什么**：答案中每条结论附引用标记 `[证据N]`，可逐级下钻 Evidence → Source → Document → ContentUnit 原文片段。

**验收标准**

- AC-1：任取一条带引用的答案，点击引用可依次打开证据、来源文档、原文片段，链路无断裂。
- AC-2：原文片段与答案句语义一致，可人工判定为「确实来自该处」。
- AC-3：构造多证据融合问题，答案引用覆盖其用到的全部证据，无遗漏引用。

**约束与备注**：引用粒度到 ContentUnit（段落/句子级），**非字符级高亮**；多轮上下文引用能力未纳入 V1.1。

### F9 答案质量门禁与降级

> 所属模块：**知识消费**
**做什么**：两道自动门禁——
① **证据忠实度门禁**：逐句校验引用完整性（completeness）与证据忠实度（faithfulness），不足则整题拒答；
② **结构化答案门禁**：逐 claim 判定 SUPPORTED / CONTRADICTED / INSUFFICIENT，含否定极性句级比对。
两者经**统一资格裁决**输出 PASS / PARTIAL / BLOCKED；PARTIAL 时仅剔除未通过的句子，其余正常交付，界面提示「另有 N 项结论…已阻止输出」。

**验收标准**

- AC-1：提出知识库中不存在的问题，系统拒答或明确声明证据不足，**不得编造**（应拒答场景正确拒答率 ≥ 0.95）。
- AC-2：构造含一条无证据支撑结论的多句答案，返回 PARTIAL 且该句被剔除，其余句子正常输出并给出提示。
- AC-3：构造与知识库相反的事实提问（如反问句），答案不被静默采纳，claim 判定为 CONTRADICTED 或 INSUFFICIENT。
- AC-4：引用准确率 ≥ 0.9（人工抽检 20 条答案，错误引用 ≤ 2 条）。

**约束与备注**：忠实度匹配为中文 bigram 词面相似度、极性判定为否定词典规则，**非 NLI 模型**；同义改写句可能被低估、复杂双重否定可能误判；误判表现为「答案少一句」，不会静默出错（L-3）。

### F10 问答可解释与 Trace

> 所属模块：**知识消费**
**做什么**：记录每次查询的路由决策、查询改写、召回通道、融合过程与耗时，提供查询历史与 Trace 明细；质量看板指标（引用准确率、无答案率、资格分布）接口已具备。

**验收标准**

- AC-1：任取一条历史问答，可查看完整 Trace：路由类型、改写前后、各路召回命中、融合权重、各阶段耗时。
- AC-2：Trace 中展示的引用集合与实际答案引用一致。
- AC-3：问答 P95 延迟（不含 LLM 生成）≤ 3s（`performance/` 基线比对）。

**约束与备注**：质量看板**无独立页面**，指标仅在 Trace 内展示；Trace 明细保留在库，无自动归档清理。

### F11 知识图谱查询

> 所属模块：**知识消费**
**做什么**：基于 Neo4j 的实体邻域查询（1—2 hop）与证据作用域投影；提供权威性图生成屏障与代次管理（权威清单未就绪时禁止图生成）；图不可用时自动降级不阻断主流程。

**验收标准**

- AC-1：选中一个实体可查询其 1 跳与 2 跳邻居，节点/关系列表完整，且结果受权限作用域约束。
- AC-2：停止 Neo4j 后问答主流程仍可用（降级），恢复 Neo4j 后图查询恢复正常。
- AC-3：权威清单未就绪时，图生成被屏障拦截并给出明确提示，不产出脏代次。

**约束与备注**：**仅 1—2 跳**，无个性化 PageRank、无社区发现与全局摘要检索；图谱可视化无画布拖动与路径高亮（增强项 G3 相关）；强依赖 Neo4j 可用性。

### F12 权限、审计与回答侧过滤

> 所属模块：**系统认证**
**做什么**：资源 ACL 变更即时生效并异步重建索引权限面；提供主体/角色查看、访问审计与 ACL 变更流水；问答侧按请求权限标签过滤证据，不引用无权内容。

**验收标准**

- AC-1：为某文档设置 ACL 标签后，无该标签的账号提问，答案中不出现该文档内容，引用列表也不包含它。
- AC-2：ACL 变更后，异步传播完成前存在短暂滞后窗口；传播完成后检索结果与新权限一致。
- AC-3：审计流水中能查到本次访问与 ACL 变更记录，含操作时间与目标资源。

**约束与备注**：**V1.1 不提供内置账号体系**（L-1），身份由内网部署 + 反向代理/网关统一鉴权注入；权限标签由上游保证可信；主体/角色仅只读查看；无审计导出与留存策略配置；ACL 重建编排（start / qualify / activate）无前端入口（G8）；**`X-Ops-Token` 仅覆盖 `/api/knowledge/index/**` 写接口**（GET=1 级、replay/skip=2 级、其他写=3 级）。

### F14 索引运维与蓝绿发布

> 所属模块：**系统配置**
**做什么**：Outbox 指标（Pending / Retry / Dead，`/index/outbox/{kb}/stats`）、死信重放与跳过、索引漂移检测（`/index/drift/{kb}`）、蓝绿索引重建 / 激活 / 回滚（`/index/schema/{kb}/rebuild` → `/activate/{releaseId}` → `/rollback/{releaseId}`）。

**验收标准**

- AC-1：Outbox 指标可实时看到 Pending / Retry / Dead 数量，注入一条失败事件后 Dead 计数 +1。
- AC-2：对 Dead 事件执行重放后恢复成功；执行跳过后事件不再重试。
- AC-3：执行一次完整蓝绿流程：rebuild → activate → 抽查问答结果一致 → rollback → 问答结果与重建前一致。
- AC-4：`GET /index/drift/{kb}` 漂移数为 0（升级后必查项）。

**约束与备注**：**前端仅列表无操作入口**（缺口 G4 / G5 / G6），需带 `X-Ops-Token` 调用接口；重建期间为双写，磁盘需预留；漂移检测后不自动修复，需重放或重建；无重建进度与预计完成时间展示，只能通过 Outbox 指标间接判断。

## 4. 版本级验收门槛（整体放行条件）

上述功能逐项通过之外，版本整体必须满足以下 7 条出口标准：

1. **端到端闭环**：新环境 30 分钟内完成 上传 → 抽取 → 裁决 → 发布 → 提问 → 追溯到原文，全程无需调接口或改库。
2. **证据可追溯**：任一条答案引用可下钻至 ContentUnit 原文，无断裂。
3. **无证据不结论**：无相关知识时必须拒答或声明证据不足。
4. **发布可回滚**：完成一次蓝绿重建 + 回滚演练，回滚后问答结果一致。
5. **权限不越界**：无权限用户的答案中不出现无权证据。
6. **稳定性**：Outbox 死信 0、索引漂移 0、72 小时无 OOM 与任务堆积。
7. **文档齐备**：部署手册、备份恢复演练记录、Go/No-Go 清单、发版清单均已交付。

质量与性能门槛（实测口径见 `docs/release/V1.1-FEATURE-SCOPE.md` §5.2）：Recall@10 ≥ 0.85、MRR ≥ 0.7、引用准确率 ≥ 0.9、正确拒答率 ≥ 0.95、问答 P95 ≤ 3s（不含 LLM 生成）、单文档（≤2MB）处理 ≤ 60s。

## 5. 全局约束（交付必须告知客户）

| # | 约束 | 影响 | 规避方式 |
|---|---|---|---|
| C-1 | **无内置身份认证** | 无法区分操作者，审计主体不完整 | 内网部署 + 反向代理/网关统一鉴权（LDAP/SSO），由网关注入身份头 |
| C-2 | 知识对象**只做状态退役，不做物理删除** | 磁盘只增不减 | 靠 EXPIRED / SUPERSEDED 保证检索面干净，确需清理走运维脚本 + 审计 |
| C-3 | 答案门禁为**词面算法**（中文 bigram + 否定词典） | 改写句/长句可能被低估，个别句子被误判 | claim 级降级保证「宁可少答，不可错答」；误判表现为少答一句 |
| C-4 | **ai-service 单实例**，未启用 ES/Milvus 时索引落本地卷 | 不可水平扩展，实例重建依赖卷恢复 | 生产规模启用 ES + Milvus；单实例场景必须卷备份 |
| C-5 | **Reranker 默认关闭** | 排序质量依赖融合策略 | 镜像加装 torch 系依赖并置 `RERANKER_ENABLED=true` |
| C-6 | **单租户多知识库**，无联邦检索、无配额限流 | 多团队共享一套实例 | 按库隔离 + 网关侧限流 |
| C-7 | **无内置定时调度**（过期扫描、备份、巡检均需外部触发） | 治理动作依赖运维 | crontab / CronJob / 外部调度器调用既有接口 |
| C-8 | **规模承诺需压测确认** | 超规模性能未验证 | 建议先按 ≤5 万文档、≤500 万向量、20 并发问答承诺，实测后再调整 |
| C-9 | 抽取与改写质量**强依赖所选 LLM** | 换模型效果波动 | 换模型后跑回归评测与种子集 |
| C-10 | 上传**单文件 100MB**，仅 PDF/Word/Markdown/文本 | 扫描件、PPT、Excel、HTML 无法接入 | 先转为带文本层的 PDF、Markdown 或纯文本 |
