1. 设计基线与总体原则

知识生成主页面交互约束：左侧不再出现“文档导入、连接器、生成任务、知识裁决、知识衍生”等二级菜单。主页面顶部使用四个任务入口卡片：导入文档 / 连接数据源 / 知识裁决 / 知识衍生；下方使用 生成概览 / 文档导入 / 连接器 / 生成任务 / 知识裁决 / 知识衍生 Tab 组织完整工作区。

详细设计承接 PRD V2.1，将产品从“功能模块集合”重构为围绕知识资产的五个用户任务域：看知识、建知识、找知识、接知识、管平台。

知识工作台看知识
知识生成建知识
知识检索找知识
知识集成接知识
系统配置管平台
术语调整：“知识集成”比“知识应用”更准确。该一级菜单的核心不是在平台内创建各种终端应用，而是把可信知识能力通过 API、MCP、SSE、SDK/凭证等方式接入现有业务系统、AI 应用、Agent 与工作流。

原则详细设计约束

2.2 主题与视觉规范（深浅双主题）

呈现层不再按页面各自调色，所有组件只消费一套主题 token：同一个语义在深色与浅色下取不同值，组件只写“主文本 / 次级表面 / 成功态”这类语义，不写具体色值。新增一个主题只需新增一组变量，不改任何组件。

2.2.1 主题切换与作用域

项规则
切换入口顶栏右侧；切换后整站（含顶栏、侧栏、弹窗、抽屉、表格、图谱画布）同步变化。
持久化本地存储保存选择，刷新与重新登录保持；未选择时跟随系统 prefers-color-scheme。
作用域主题作用于根节点的 data-theme，所有变量在该作用域下重定义；组件无需感知当前主题。
对比度正文与背景对比度不低于 4.5:1；弱化文字不低于 3:1；状态色在两种主题下都必须落在“可读”区间。

2.2.3 按钮三档

档位形态用于两主题表现
主操作品牌色实心 + 白字 + 品牌色边框页面唯一主行动点：生成知识、开始导入、发布服务形态一致，仅品牌色深浅不同
次操作表面底 + 可见边框 + 主文本刷新、重试、预览、批量操作边框在深色下必须可见，否则会退化成一块看不出边界的深色
弱操作无边框 + 次级文字，hover 才出现底色取消、关闭、次要链接同上
危险操作危险色实心 + 白字删除、停用、废止同上
切换类按钮（如“文档 / 文本分块 / 实体归一”）统一写成「次操作 + 选中即切主操作」，并依赖样式层顺序保证主操作覆盖次操作；禁止用透明度、下划线或自绘底色表示选中。

2.2.4 状态三件套与状态胶囊

任何位置展示“成功 / 警告 / 失败 / 进行中 / 中性”，一律使用同一枚状态胶囊：底色 + 字色 + 边框三件套由主题给出，深浅各一套。

2.2.5 第三方组件的主题桥接

表格、标签、按钮、进度条、弹窗、分页等基础组件来自 Element Plus，其默认皮肤是浅色的。做法是把组件的 CSS 变量整体接到本套 token 上（背景、文字、边框、填充、状态色及其浅色变体），使它们在深色主题下自动变成深色底 + 亮色字，在浅色主题下使用本套状态色，而不需要逐个组件写主题分支。

收益：状态色在“自己写的胶囊”和“第三方组件的标签”上完全一致；新增主题时第三方组件自动跟随。

2.2.6 实施纪律

禁止替代做法
在组件里写固定调色板色（如“浅绿底 + 深绿字”）使用状态胶囊类，配色由主题给出
用品牌色原色当文字色使用强调文字色（深色下更亮、浅色下更深）
用灰色写死边框、分割线使用分割线 / 边框变量
用透明度表示禁用或弱化使用弱化文字色与禁用态样式
每个页面自定义按钮与标签使用按钮三档与状态胶囊

4. 知识生成详细设计

路由：/knowledge/generate。首页以四个任务卡为核心：文档导入、连接器、知识裁决、知识衍生，下方展示最近生成任务。

4.1 文档导入向导

Step 1 来源 → Step 2 文件/URL/文本 → Step 3 知识属性 → Step 4 处理策略 → Step 5 执行与结果
步骤字段规则
来源知识空间、来源名称、来源类型空间默认当前值
内容File/URL/Text批量文件显示大小、类型、重复检测
知识属性知识类型、标签、权限、有效期权限默认继承空间，可收紧
处理策略标准/高质量/自定义高级设置才暴露 Parser、Chunk、模型
执行Pipeline Progress异步；允许离开页面，任务中心继续跟踪

4.2 连接器

连接器列表使用卡片+表格混合视图：类型、名称、同步状态、最后同步、对象数、权限策略。创建流程统一为“选择类型 → 认证 → 范围 → 字段/权限映射 → 同步策略 → 测试连接 → 创建”。

4.3 解析/抽取结果

用户点击生成任务进入任务详情，展示 Document → Parse → Chunk → Extraction → Evidence → Candidate Knowledge。专业用户可打开“原文/结构/Chunk”三栏工作台。

4.4 知识裁决

知识裁决
左：冲突/待审核列表 中：Assertion A Assertion B 值 / 条件 / 版本 / 置信度 值 / 条件 / 版本 / 置信度 右：Evidence 原文 / 来源 / 页码 / 权威度 系统建议（辅助，不自动决定） [采用 A] [采用 B] [合并] [全部拒绝] [要求补充证据]

4.5 知识衍生

包含三个 Tab：衍生规则、候选衍生知识、运行记录。候选详情必须展示 baseAssertionIds、derivationType、rule/algorithmVersion、graphPath、confidence 和 Evidence；基础知识变更后标记 STALE。

4.6 摄入运行日志

左列为已上传文件 / 运行记录，右列为该次运行的时间线（接入 → 解析 → 入库 → 抽取 → 建索引）。左列每行展示状态点 + 文件名 + 阶段与时间 + 状态胶囊；状态胶囊显示中文状态（成功 / 失败 / 进行中 / 排队中 / 已取消），不展示后端枚举原文。选中行使用强调底色 + 左侧强调竖条，与 hover 态区分。上传进行中时日志跟随最新事件滚动。

5. 知识检索详细设计

路由：/knowledge/search，顶部 Tab：搜索｜检索测试｜检索策略｜检索链路追踪（Query Trace）｜知识图谱｜检索评测（Benchmark）。「检索测试」与「检索链路追踪」属于调试类页面：配置区 + 结果区 + Trace 抽屉。

5.1 搜索

[自然语言或关键词................................] [搜索] 过滤：来源 | 知识类型 | 标签 | 状态 | 时间 | 对象类型 结果 1 [知识卡片] 标题 / 摘要 来源 · Evidence · 版本 · ACTIVE 关联断言 5 · 相关实体 3 [查看详情] 结果 2 [断言] ...

默认混合返回 Card、Assertion、Document、Entity。结果对象必须显示来源与状态，禁止只返回无法解释的向量片段。

5.2 检索测试

左侧 Query/策略配置，右侧结果；结果展开 Score Breakdown：BM25、Vector、RRF、Rerank、Business Weight。点击“Trace”打开 Drawer 查看各阶段输入输出与耗时。

5.3 Retrieval Profile

Profile 采用“基础设置 + 高级设置”。基础设置仅包含知识范围、搜索模式、TopK；高级设置包含权重、阈值、RRF K、Reranker、Graph Expansion、Context Window。

5.4 检索评测（Benchmark）

数据集管理、运行历史、版本对比。至少显示 Hit@1/3/5、Recall@K、Citation Accuracy、Latency；P1 增加 MRR/NDCG/Faithfulness。

5.x 知识图谱检索工作区（V2.1 新增）

知识图谱属于“知识检索”主页面内部的高级检索 Tab，不新增左侧菜单。其定位不是独立的图数据库管理后台，而是帮助用户通过实体、关系、路径和 Evidence 理解“知识之间为什么有关联”。

图谱画布Entity 为主要节点；Relation 为边；Assertion/Evidence 作为可展开关联对象单击节点查看详情；双击/展开加载下一跳

6. 知识集成详细设计

知识集成负责把平台的可信知识能力安全、标准化地接入外部系统。设计上参考成熟云产品的“数据资源与服务资源分离”思路：知识资产本身与面向调用方的集成服务是不同对象。

6.1 信息架构

知识集成 ├─ 集成概览 ├─ 服务 │ ├─ Search Service │ ├─ Retrieve Service │ ├─ Answer Service │ └─ Knowledge Object Service ├─ API ├─ MCP ├─ SSE ├─ 凭证与访问控制 └─ 调用日志 / Trace

6.2 集成概览

区域内容
服务 KPI服务数、今日调用、成功率、P95、错误数
协议分布REST / MCP / SSE 调用量
健康状态正常、限流、凭证过期、模型/索引异常
最近调用client、service、query、status、latency、traceId

6.3 创建集成服务

Step 1 基本信息 名称 / 描述 / 环境(dev,test,prod) → Step 2 知识范围 Knowledge Space / Source / Tag / Knowledge Type → Step 3 检索能力 Retrieval Profile / 是否生成 Answer / Citation → Step 4 协议 REST API / MCP / SSE → Step 5 安全 Credential / Scope / IP / Rate Limit / Expiration → Step 6 测试并发布

6.4 REST API

接口用途主要输出
POST /v1/search搜索知识对象Card/Assertion/Document/Entity + scores
POST /v1/retrieve为外部 LLM/Agent 提供 ContextEvidenceBundle + citations + traceId
POST /v1/answer平台完成检索与生成Answer + Citation + Knowledge refs
GET /v1/knowledge/{type}/{id}读取知识对象Object + lineage + version

6.5 MCP

MCP 页面分为 Server 配置、Tools/Resources 列表、权限范围、测试控制台和调用日志。建议首批工具：search_knowledge、retrieve_context、get_knowledge_card、get_assertion、get_evidence、explore_entity。MCP 不建立第二套权限模型，复用集成服务 Credential + Knowledge ACL。

12. 异常、空态与审计

场景产品行为
空间无知识工作台显示 onboarding：导入文档 / 创建连接器，而不是全屏 0 指标。
解析失败显示失败 Stage、错误摘要、重试；高级模式展示技术日志。
搜索无结果给出过滤条件提示、相近 Query、Knowledge Gap 反馈入口。
证据不足Answer 可返回“证据不足”，并展示已检索到的相关知识。
越权不泄露对象是否存在；审计记录 deny reason。
集成凭证失效401/403 标准错误；控制台显示凭证状态和最近失败。

13. 响应式与交互规范

桌面端为主要知识工程工作台；≥1440px 内容最大宽度建议 1600px，复杂页面允许全宽。Drawer 用于轻量详情和 Trace；需要原文对照、图谱、裁决的复杂任务使用独立页面。所有异步操作返回 taskId 并提供全局任务状态。

13.1 主题与状态呈现

场景规范
主题切换顶栏常驻入口，随时可切；不得把主题设置藏在系统配置里。
状态呈现列表状态列、日志运行列表、批量文件行、详情头部统一使用状态胶囊；状态点仅作辅助。
状态文案展示中文状态（成功 / 失败 / 进行中 / 排队中 / 已取消），前端负责枚举翻译。
加载与空态骨架屏、空态、错误态使用与主题一致的表面与文字层级；错误态使用失败色，不使用红色实心块。
异步反馈进行中使用警告色，成功使用成功色，失败可重试并在文案中给出下一步动作。

13.2 断点与密度

≥1440px 全宽复杂页；1100–1440px 双列降为单列或保持双列但压缩内边距；≤1100px 侧栏收起为图标条，卡片网格降为两列；≤720px 仅保证查看与关键操作，复杂编辑类任务提示使用桌面端。
