1. 技术规格总览

双语言双进程

Java（Spring Boot）承担控制面：事务、权限、版本、治理、编排与审计；Python（FastAPI）承担计算面：解析、抽取、向量检索、图算法、查询编排。

知识对象化

一等对象是 Evidence / Claim / Knowledge / Card / Entity / Relation，Chunk 仅作为证据载体，召回后仍要回到证据本身。

索引皆派生

ES / Milvus / Neo4j 全部是可重建投影，MySQL 是唯一权威事实源；任何索引重建都不得改变业务状态。

5.2 分块与解析规格

CHUNK_SIZE    = 900    # 字符
CHUNK_OVERLAP = 120    # 字符
保留字段：code / heading path / page / offset / parent_id
产物：ContentUnit（层级） + StandardDocument（归一化 → llmkb_standard_doc_v1）
  • 保留位置信息是为了让 Evidence 可定位回溯（location_json），这是答案引用可核验的前提。
  • 标准文档库是生产中间态，与面向检索的知识索引解耦，便于重跑抽取而不影响线上检索。

5.3 LLM 抽取契约

抽取结果必须是可直接入库的结构化 JSON 载荷，而不是自由文本。缺失字段由流水线补中性值，避免模型输出抖动导致链路中断。

{
  "entities": [{"name": "Tomcat 8.5", "type": "SOFTWARE", "aliases": ["Tomcat8.5"]}],
  "claims": [{
      "subject": "Tomcat 8.5", "predicate": "SUPPORTS", "object": "PKCS12",
      "conditions": ["JDK >= 8"], "qualifiers": {"env": "prod"},
      "polarity": "POSITIVE", "certainty": 0.9,
      "valid_from": null, "valid_to": null
  }],
  "cards": [{"type": "Procedure", "title": "...", "content": "...", "confidence": 0.8}]
}
质量边界：抽取质量随所选 LLM 波动；缺少适用条件或有效期的断言在裁决侧按低确定性处理，不会被当作普适事实自动批准。

5.4 实体归一算法（两级判定 + 降级）

提及 Mention → 归一化（大小写 / 空格 / 标点 / 中英文） ↓ ① 别名词典匹配 → 命中 canonical entity，confidence = 1.0 ↓ 未命中 ② 向量相似度 → cosine ≥ ENTITY_RESOLUTION_SIMILARITY（0.86）取最优锚点 ↓ 未命中 ③ 新建实体，并将提及写入 t_entity_alias（幂等，带 alias_type / confidence） 产出：merges（from → to，源实体置 MERGED，链接重定向） aliases（表面形式入库） entities（归一化清单，供后续批次复用）
  • 开关与阈值：ENTITY_RESOLUTION_ENABLED=true、ENTITY_RESOLUTION_EMBEDDING_ENABLED=false、ENTITY_RESOLUTION_SIMILARITY=0.86。
  • 降级策略：归一是质量增强而非正确性闸门。AI 服务不可用或向量能力关闭时仅走词典；两者都不可用则保持“未归一”继续运行，任务摘要标记 degraded，绝不因归一失败中断抽取。

5.5 冲突检测算法（时态感知）

时态关系判定处理
DISJOINT（有效期无交集）不记为冲突视为版本替代，避免“新版本 vs 旧版本”误报质量事故
OVERLAPPING（窗口重叠且结论互斥）冲突score × 0.85 折减，标记 temporal，交裁决区分优先级
UNKNOWN（任一侧缺有效期）退化为普通冲突不享受时限豁免
互斥判定口径：同 subject + predicate，object / value 不同或 polarity 相反，
且 qualifier_json 在可比口径下等价 → 判为冲突并记录 t_knowledge_conflict（resolution 待裁决）
设计取舍：把“版本演进”与“事实冲突”分离，冲突率才是可信质量指标；否则每次版本升级都会污染告警，运营很快会忽略它。

5.6 裁决状态机

Candidate → 重复检测 → 语义合并 → 冲突检测 → 证据 / 权威 / 时效评分 ↓ AI Judge： APPROVED │ SUPPORTED │ PARTIALLY_SUPPORTED │ UNCERTAIN │ CONFLICTED │ REJECTED ↓（按风险与置信度路由） 人工复核 Human Review → EFFECTIVE / EXPIRED / SUPERSEDED
硬约束：低置信度、高风险、强冲突、生产配置类知识不得仅由 LLM 自动批准，必须进入人工复核或双证据校验。

5.7 生命周期三种流转

流转触发条件系统动作接口
到期失效valid_to < now置 EXPIRED → 写版本快照 → 投递 Outbox 索引事件POST /api/knowledge/lifecycle/{kb}/expire
版本替代新知识对象显式声明替代关系旧对象置 SUPERSEDED，保留历史与 SUPERSEDES 关系，不物理删除POST /api/knowledge/lifecycle/{kb}/supersede
影响分析源文档撤销 / 删除按受影响自治范围计算 CARD / CLAIM / ENTITY 影响面（只算不删）GET /api/knowledge/lifecycle/sources/{sourceId}/impact
边界：生命周期引擎接口已就绪，但无内置定时调度与治理看板；到期扫描需由外部触发（cron / 运维脚本 / 面板按钮）。影响分析只做计算与呈现，是否退役由人或后续裁决决定，避免源文档误删造成不可逆损失。

6. 索引与检索基础设施

6.1 索引器职责

KnowledgeIndexer
  _external_providers()    按 RETRIEVAL_MODE 选择 ES / Milvus / external 组合
  _permission_tags(item)   把对象权限标签投影为索引过滤字段
  _acl_allowed_ids(rows, tags, admin)   结果侧本地 ACL 兜底过滤
  _knowledge_rows()        构造 Card / Claim / Entity 索引行（含 authority / freshness / confidence / evidence_count）
  _normalize_snapshot_document()   写入侧文档规范化
原则：索引行必须携带 knowledge_base_id、permission_tags、status 与质量信号字段；否则融合阶段只能取中性值，等于放弃提权。

6.2 双检索模式

7. 查询与答案生成：技术原理与程序流程

POST /api/knowledge/query（生成 qid） ↓ AiClient → POST /ai/query ① QueryRouter.route(q) 确定性关键词判别 → questionType / strategies / matchedRule ② QueryRewriter.rewrite(q) 同义词词典（确定性）+ 可选 LLM（≤2 候选）→ ≤4 改写集 ③ QueryEngine._recall(...) 按 strategies 并发多路召回（BM25 / Vector / Card / Claim / Graph） ④ Fusion Weighted RRF + QualityBoost ⑤ Reranker 可选，默认关闭 ⑥ _context() / _prompt() 上下文装配（CONTEXT_MAX_CHARS = 8000） ⑦ LLM 生成 answer + citations ⑧ AnswerQualification 双门禁 → 判定 / claim 级局部降级 ⑨ 回写 t_query_trace 与 answer-qualification

7.1 路由判别规则

问题类型代号主策略增强策略
事实 / 定义FACTCard + Vector + BM25Claim + Evidence
专有名词 / 错误码EXACTBM25Vector
关系问题RELATIONEntity + GraphVector
多跳问题MULTIHOP有界图遍历（1—2 hop）Card + Evidence
全局总结GLOBAL向量宽召回（社区摘要未实现）Vector
SOP / 操作PROCEDURECardEvidence + Vector
条件 / 规则CONDITIONClaim + ConditionGraph
冲突 / 版本CONFLICTClaim 冲突检索Source 版本
  1. 关键词驱动：插件化关键词表，零模型依赖、高可解释。
  2. 最长命中优先：多规则同时命中时取最长关键词所属类型（如“哪个版本”优先于“配置项”）。
  3. 回退 FACT：无关键词命中时按事实 / 定义处理，而不是退化为纯向量检索。
  4. 决策入 Trace：questionType / strategies / matchedRule / matchedKeyword 全部落库，可复盘。
能力对齐：社区摘要（Community Summary）与 Personalized PageRank 未实现，对应策略降级为“向量宽召回 / 有界图遍历”，并在 Trace 的 reason 中显式标注，避免隐性能力夸大。

7.2 查询改写

QUERY_REWRITE_ENABLED=true        # 确定性同义词词典，始终可用
QUERY_REWRITE_LLM_ENABLED=false   # LLM 改写，最多 2 个候选，失败即跳过
改写集去重后 ≤ 4；候选不足时用剩余改写触发补充召回（最多 2 轮）
LLM 不可用时链条退化为单路召回，不得报错；补充召回有界，避免同义扩散打爆 Token 预算。每轮改写来源、实际用词与耗时均计入 Trace。

7.3 融合公式

WeightedRRF(d) = Σ  w_channel_i · 1 / (k + rank_i(d))        # k = RRF_K（默认 60）

QualityBoost(d) = 1
  + wa · Authority(s)      # 来源权威性，缺失取 0.5
  + wf · Freshness(t)      # 时效性半衰：0.5^(ageDays/365)，下限 0.2
  + wc · Confidence(c)     # 抽取 / 裁决置信度，缺失取 0.5
  + we · Evidence(e)       # 证据条数归一化 0~1

Final(d) = WeightedRRF(d) · QualityBoost(d)
默认权重：wa=0.15  wf=0.10  wc=0.15  we=0.10（FUSION_WEIGHT_* 可覆盖）
  • 质量信号必须在索引阶段写入，否则融合阶段只能取中性值。
  • 缺失字段取中性值而非 0，避免历史索引被系统性压低。
  • 权重可由环境变量覆盖，便于离线用 Recall@K / MRR / NDCG 重新标定而不改代码。

7.4 重排序（Reranker）

RERANKER_ENABLED=false（默认）  RERANKER_PROVIDER=bge  RERANKER_MODEL=BAAI/bge-reranker-v2-m3
RERANKER_DEVICE=auto  RERANKER_BATCH_SIZE=4  RERANKER_CONCURRENCY=1
RERANKER_MAX_LENGTH=1024  RERANKER_MAX_CHARS=6000
  • 需要 ML 运行时（INSTALL_ML=true）；未安装时静默降级，不影响主链路。
  • 并发默认 1 是为保护小显存 GPU，避免 OOM。

7.5 答案双门禁

门禁默认阈值判定内容失败行为
证据门禁（Evidence Gate）ANSWER_FAITHFULNESS_MIN=0.03答案是否有 Evidence 支撑（支持度 / 完整度）整体不通过则降级或拒答；已实现 claim 级局部降级，保留可支持部分
蕴含门禁（Entailment Gate）ANSWER_ENTAILMENT_MIN=0.08答案文本与召回证据的蕴含关系
技术边界：蕴含判定为词面算法（中文 bigram 重叠 + 否定词典），不是 NLI 模型。它能拦住“明显无据”的答案，但不能替代真正的语义蕴含；关键场景仍需人工复核。策略版本由 ANSWER_POLICY_VERSION 标识并写入 Trace。

11. 一致性、幂等与降级

事务边界

业务写操作在 backend 单库事务内完成（元数据 + Outbox 事件同行提交）；AI 服务不参与跨库事务。

最终一致

Outbox 事件驱动 ES / Milvus / Graph 追赶；失败可 replay，确认无效可 skip，并用 drift 端点核对差异。

幂等

上传按内容哈希去重；实体别名幂等写入；索引以主键 / _id 覆盖写。

并发控制

Redis 用于重建与批处理任务的幂等锁，避免并发重建互相覆盖。
故障降级路径
LLM 不可用抽取 / 改写 / 生成按 mock 或跳过；查询链路退化为单路召回，不报错
Embedding 不可用回落到 hash 向量或纯 BM25 通道
ES / Milvus 不可用auto 模式回落本地 index_store；external 模式下失败上抛
Neo4j 不可用图通道跳过，Trace 标注降级原因
Reranker 缺失跳过重排，保留融合顺序
本地索引缺失按空结果处理，不得误判为运行错误

12. 权限与审计技术实现

  • 模型：资源属性级 ACL（对象携带 permission_tags），无网关注入身份时按“内网可见”处理。
  • 传播：标签变更后异步重算 ACL 索引行（/ai/index/object/acl）；一次完整重建走 /acl/rebuild/{changeCode}/start → qualify → activate。
  • 审计：访问决策写入 t_acl_access_audit（含 decision 与 reason），ACL 变更留痕可查。
  • 回答侧：召回与装配双重过滤，确保越权证据不进上下文。
V1.2 缺口：平台无登录过程、无用户实体、无会话；t_knowledge_base 无可见性字段，知识库公开 / 私有划分未提供；用户增删改查亦未提供（现仅 /acl/subjects、/acl/roles 只读查询）。V1.1 依赖内网部署 + 网关统一鉴权。

14. 非功能规格要点

性能

检索超时 5s（RETRIEVAL_TIMEOUT_SECONDS）；AI 读超时 180s；上下文上限 CONTEXT_MAX_CHARS=8000；批量写入 200/批。

容量

向量规模随 EMBEDDING_DIM 与文档量增长；MySQL 为状态基线，索引层可整体重建。

可用性

任一层降级不影响元数据正确性；索引重建走影子版本 + 读目标原子切换。
